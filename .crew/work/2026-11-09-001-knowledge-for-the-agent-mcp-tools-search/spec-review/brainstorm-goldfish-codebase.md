## Findings
- F-1 · Blocker · What exists today, scripts/plugins.ts bullet and The tools, agent id paragraph · `scripts/plugins.ts` only writes the plugin MCP commands for Claude Code, Codex and Cursor (`.claude-plugin/plugin.json`, `plugins/codex/.mcp.json`, `plugins/cursor/mcp.json`). Claude Desktop's `["mcp", "--global"]` comes from `src/install/claude-desktop.ts:81`, and the installed hosts' MCP commands come from `src/install/claude-code.ts`, `src/install/codex.ts`, `src/install/copilot.ts` and `src/install/hooks-file.ts:236,390`. A build that edits only plugins.ts leaves `claude-desktop`, Copilot and the installed hosts writing as `mcp`.
- F-2 · Blocker · The judgements, Duplicates and contradictions ("the existing interface") · `ConsolidateInput` in `src/judge/types.ts:47-51` takes `draft.kind: MemoryKind`, a required `files: string[]` and neighbours with `id: number`. Part 1's entries have UUID ids and their own kinds, and `ConsolidateVerdict.perNeighbour[].id` is a number. The TypeSafe state in `src/judge/questions.ts:219-253` labels the draft `new_memory` and asks about memories. So entries cannot go through `Judge.consolidate` unchanged, as the concept says they can.
- F-3 · Major · The judgements, Cataloguing and Relevance · `withFallback` (`src/judge/fallback.ts:42-66`) builds a new judge with `distill`, `consolidate` and only `personal?`, and `makeJudge` returns that wrapper. A new `catalogue?` or `relevant?` on `TypeSafeJudge` would be dropped whenever a key is set. The concept does not name the changes needed in `fallback.ts`, `typesafe.ts` and `heuristicJudge` (the area lexicon), or what each one falls back to.
- F-4 · Major · The judgements, Duplicates and contradictions · `DUPLICATE` in `src/distill/policy.ts:21` also needs `contradicts < 0.5`, and `SUPERSEDE` needs `relationScore >= 0.8`. `consolidate.ts` checks replacement before duplicate. The concept's rules ("same, 1.5 or more" refuses; "0.7 or more" records a contradiction) do not say which wins when one neighbour is both same and contradicting, so a builder could refuse a correction as a duplicate.
- F-5 · Major · Design sketch, The module (BUILT_IN, DEFAULTS) · ADR 0019's closing decision (docs/adr/0019-one-engine.md:74) is that knowledge and personas "are not modules of wizardingcode-mem but a product of their own", and ADR 0020 is withdrawn. The concept reverses both but names no new ADR that supersedes them. A reader of the ADRs will think the design forbids it.
- F-6 · Major · What exists today, compose bullet, and The module · F5′ also changes what `compose` asks first and joins: ADR 0020 asks declared modules first and outputs in engine order. The concept omits two things ADR 0020 needed for this: the `MomentInput` additions (`modules`, `projectRoot`, since the repository root is not the hook's `root`/cwd) and the K8 module migrations. `EngineModule` (`src/engine/module.ts:73-94`) has neither today.
- F-7 · Major · What the agent is shown, Prompt ("the FTS5 search") · Part 1's spec says "No full-text index and no search command: part 2 adds them". No knowledge FTS5 table exists, and none is said to be created. The concept does not create it, keep it in sync with part 1's writes, `rebuild` and `adopt` (ADR 0020 used triggers on `knowledge_fts`), or create `knowledge_shown`, and it assigns no migration owner.
- F-8 · Major · What the agent is shown, Session start and Prompt · Part 1's `ensureFresh` compares head and fingerprint before a read. The concept does not say whether the hook calls it, which costs directory listings and perhaps a git process (the brief forbids processes in a hook), or reads a possibly stale index. ADR 0020 needed an explicit rule here (K5).
- F-9 · Major · What exists today, src/store/sessions.ts bullet ("first session") · `touchSession` runs on every hook event before `compose` (`src/hooks/handle.ts:67`), and `ensureSession` (backfill/history import) creates `sessions` rows too. Three cases lose the project's only chance at the pinned entries without anyone being told: a project whose history was imported, a first session whose first hook was a prompt or a tool event, and a host without `sessionInjection` or a `resume` start (handle.ts:118 skips compose). The concept also does not say whether `/clear` or a compact in the first session shows the pinned entries again.
- F-10 · Major · What the agent is shown, Wrapper · `withoutNotes` (`src/retrieve/render.ts:91-113`, used by `src/distill/pipeline.ts:225-226`) strips only `<wizardingcode-mem-notes>` blocks and note-shaped lines. If the agent echoes a `<wizardingcode-knowledge>` block, distillation keeps it and saves knowledge back as a memory. The concept does not extend the stripping.
- F-11 · Major · observability · tracing a shown entry · `knowledge_shown` (session, epoch, repo, entry) records neither the moment (memory's `injections` record `event`) nor the entry's version or hash. Entries are versioned, so after an edit nobody can tell which text the agent saw, or whether it came from session start or a prompt.
- F-12 · Major · observability · the prompt's lexical floor · The concept records only what was shown, not which floor rule let an entry through (code name, three words, or title plus one) nor the candidates it rejected. The one known leak of the ADR 0020 floor ("User roles") could not be diagnosed from the store at 3 AM.
- F-13 · Major · observability · a judge's decision on a proposal · Only `contradicts: <entry id>` reaches the proposal frontmatter. The concept records nowhere the verdict's `source` (typesafe, heuristic, or fallback after a breaker trip), judge `version`, `relationScore`, contradiction probability, or the catalogue choice and its confidence. Memories record their judge version (types.ts:81, status shows memories by judge). Refusals (duplicate, no area) leave no trace a person can see.
- F-14 · Major · observability · TypeSafe cost and the breaker · `USAGE_KEYS` (`src/judge/index.ts:20`) counts requests and tokens in one total. The search rerank (up to 20 Nouls per call) and cataloguing would be mixed with distillation in `status`, and the single `Breaker` per key fingerprint means search failures trip the breaker for distillation too. The concept says nothing on either.
- F-15 · Major · observability · status and doctor · `src/status/report.ts` and `src/doctor/checks.ts` show nothing about modules today. The concept does not say how `status` shows that knowledge is on, the counts of pinned and active entries, entries shown, or open agent proposals, nor what part 1's `doctor` knowledge line adds for the index, `knowledge_shown` and the FTS table.
- F-16 · Major · observability · silent drop in compose · `compose` (`src/engine/compose.ts:30`) drops a contribution longer than its budget with no `onError` call. A knowledge render that overruns its 840 or 480 characters by a separator or an inert-escape would vanish with no log. The concept relies on the module measuring itself and names no signal for this.
- F-17 · Major · The tools, agent id · Without `--agent` the writer is `mcp`, and every existing installation's configuration was written without it. The concept does not say whether `install` or `doctor` rewrites or flags old entries. Until then, proposals cannot be traced to a host, which part 1's guarantee depends on.
- F-18 · Major · Acceptance, perf budgets · The corpus in `tests/perf/budgets.test.ts` holds memories only. With knowledge on and no entries, "the budgets hold" measures nothing of the knowledge path. The concept does not say the perf corpus gains entries, pinned ones and a first-session start.
- F-19 · Nit · What exists today, tests bullet · `tests/unit/hook-snapshots.test.ts` does not set `WIZARDINGCODE_MODULES`. It passes deps without `modules`, so `handleHook` falls back to `enabledModules(undefined)`, the code default (handle.ts:112). Only mcp-tools-list sets it blank. Changing `DEFAULTS.modules` therefore turns knowledge on in the hook snapshots too.
- F-20 · Nit · The tools, `--global` · `GLOBAL_INSTRUCTIONS` in `src/mcp/run.ts:40-45` is server text that names only memory's tools, and the concept does not update it for `knowledge_search`, `knowledge_get` and `knowledge_taxonomy` in Claude Desktop.
- F-21 · Nit · What exists today, judge bullet · The text gives `consolidate(draft, neighbours)`, but the signature takes one `ConsolidateInput` object, and `Judge` also carries `name`, `version` and `versions`.
- F-22 · Nit · Assumptions, "turns it off with the modules setting" · `enabledModules` treats an explicit list as complete, so a user whose settings file already holds `WIZARDINGCODE_MODULES=memory` never gets knowledge by default. Older binaries (plugins pin their own version) given `memory,knowledge` call `logUnknown` once per process, which is every hook. The concept does not mention either.
