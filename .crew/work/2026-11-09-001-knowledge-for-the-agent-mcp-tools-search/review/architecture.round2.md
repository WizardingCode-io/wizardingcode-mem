## Findings
- F-1 · defect · src/status/report.ts:192-199 · `knowledgeStatus` reads `knowledge_entries` (`status`, `problem`, `pinned`) and `knowledge_shown` (`at`, `repo_id`, `entry_id`) and checks only that the two tables exist. It never asks the module's schema rule. The base says (CLAUDE.md, knowledge paragraph) that `schema.ts` is "the leaf with `requireSchema`, which everything that reads or writes the tables calls". The same change follows that rule everywhere else: `contribute` stays silent unless `moduleSchemaState(...) === "current"`, `compact` prunes `knowledge_shown` only when the state is "current", and `doctor` checks for "too-new" before it counts the FTS rows. Status alone reads columns a newer binary's knowledge schema may have reinterpreted. That gives one of two results: a `knowledge … entries` line that means something else, or a thrown query that brings down the whole `status` command. This is rubric question 2 (data model: columns read under a meaning the recorded schema version does not promise) and question 6 (it breaks the module's own rule that its neighbours keep). Fix: return null, or a `knowledge tables newer than this wizardingcode-mem` line, unless `moduleSchemaState(db, KNOWLEDGE_MODULE, KNOWLEDGE_SCHEMA_VERSION) === "current"`, as compact.ts:118 does. Add a test with a module version of 8 recorded.
- F-2 · advisory · docs/adr/0024-knowledge-module.md:242 · The D-9 (part 2) row, and the spec's Design, say "One function, `showsPins`, decides whether a session start shows pins … The other answer changes the body of `showsPins` and its tests". No `showsPins` exists anywhere in src/. The decision is a comment inside `forSessionStart` (src/modules/knowledge/contribute.ts:192). Either extract the one-line function the record names, or change the ADR row to name `forSessionStart`.
- F-3 · advisory · src/judge/types.ts:57-60 · The new `ConsolidateTexts` types `body` as plain `string`, where `ConsolidateInput` and `RelateInput` carry the `Redacted` brand. `consolidateState` and `consolidateQuestions`, which build the TypeSafe request, now accept unbranded text. The entry points still require `Redacted`, so nothing leaks today, but the type no longer guards the edge where text leaves the machine. Type `body` (and the neighbours' `body`) as `Redacted`; both callers already pass branded text.
- F-4 · advisory · src/modules/knowledge/tools.ts:107 · `rootAreas` re-implements part 1's `taxonomyFor` (repo.ts:712): the same `kindAt` folder test, `readRegularFile` and `parseTaxonomy`. The only difference is that it falls back to `DEFAULT_AREAS` where `taxonomyFor` throws. A guard later added to `taxonomyFor` will not reach the area enum. Call `taxonomyFor` with a dataDir-only store, or with a small shared reader, and map a refusal to the defaults.
- F-5 · advisory · ui/src/api.ts:131-138 · The compact route now returns `knowledgeShown` (`CompactReport` in src/store/compact.ts), but the viewer's mirror type of that route was not given the field. The field is additive and harmless, but the client's copy of the route contract no longer matches the server's.
- F-6 · advisory · src/mcp/agent-id.ts:6-7 · Two JSDoc comments are stacked on `UNKNOWN_AGENT`; the first is a leftover of the second.
