## Findings
- F-1 · Nit · spec.md Design 1 "The state" / plan.md Phase 2 `UpdateState.failures` · `failures` is stored, incremented, strictly validated and tested (AC-22, the -1 and 1.5 cases), but nothing reads it: the backoff is a flat hour since the curve was rejected (Alternatives), and no line in the Design 2 table shows the count. It is state kept only for a future curve, so dropping the field (and its validation and test cases) would be simpler.
- F-2 · Nit · spec.md Design 1 (the request, `due`, `mode`, "The tests") and Design 3 ("Whether", the `decide` input fields) · the spec is written at code level: signatures with defaults, exported constant names, the order of the `due` branches, the field-by-field validation, and the test seams (`run(args, deps?)`, the preload line). plan.md Phases 2 and 5 repeat the same material. The spec should keep the behaviour and the limits, and leave the signatures and the order of the branches to the plan, so the two documents cannot drift apart.
- F-3 · Nit · plan.md Phase 1 `stagedVersion` "remembered in a module `Map`" · this is a per-process cache with no measured cost behind it. The spec's NFR already limits the calls to one `--version` (two when it stages), so passing the version that `reconcile` or `stagedFacts` already read to whatever needs it next would avoid both the cache and the rule for when to clear it (`stageBinary` deletes the entry).
- F-4 · Nit · plan.md Phase 1, sweep of stale `*.new` / `*.<digits>.new` files older than 24 h · cleanup across processes is added on top of the per-pid temporary name. A temporary file can only be left behind when a staging crashes, so the sweep (with its regex, its lstat and its ignored errors) is hardening that no stated failure asks for. Removing this process's own temporary file in a `finally`, as `writeFileAtomic` already does, would cover the case this item adds.
- F-5 · Nit · spec.md Alternatives · for problem 2 ("after `brew upgrade` the agents keep the old binary"), the Alternatives list neither a fix in the Homebrew formula (`post_install` staging, or a `caveats` line pointing to `install`) nor why it would not work, for example because Homebrew sandboxes `post_install`. The reconciliation is the main new mechanism this item adds to every reconciled command. A sentence on why the fix cannot sit in the one channel that has the problem would show that the root cause was considered.
- F-6 · Nit · plan.md Phase 5 `handOver(path, argv, say, fail?)` and Phase 3 `CHANNEL_COMMANDS.shell` · two small seams exist mainly to serve one caller or a test: the `say` and `fail` callbacks let `install` keep its exact current text, and the `shell` flag lets the README test skip the plugin's sentence. Returning the error and letting each caller print its own text, and testing the three shell commands by name, would be simpler. Low stakes.
