## Notes
- (1) The request holds. `redirect: "manual"`, one exact `Location` shape, no body, a 5 s limit, a plain version only: a captive portal or a hostile network without a trusted certificate ends as `offline` or `not a release redirect`; a TLS-inspecting proxy that forges the redirect can only make `status` print "X is out" and the four constant commands. Nothing is downloaded or executed from the answer. Keep `latest` overwritten by every success (spec.md:52 does: not forward-only), so a forged high value heals at the next good check; say so in ADR 0030 so nobody makes it monotone later.
- (1) Build the pattern anchored on the whole `Location` string and bound the digits of each number (for example 1 to 5), so a huge value cannot reach the output or the comparison.
- (1) Bun's `fetch` honours `HTTPS_PROXY`; the request then goes through the person's proxy. Worth one clause in ADR 0030's limits.
- (1) README.md:343 also contains "Nothing leaves" (the line was too long to read here); check it against the new default the same way as README.md:432.
- (1) spec.md:51 says an unknown value "read from the environment" counts as `off`; AC-3 (spec.md:100) covers an unknown value from `<data dir>/env` edited by hand too. Make spec.md:51 say both, so the build does not fall back to `check` for a hand-edited file.
- (3) `reconcile` opens no boundary `install` does not already have: whoever can write `<data dir>/bin` (mode 0700, src/install/binary.ts:50) already has their file run by every hook and by `install`'s hand-over (src/cli/commands/install.ts:245), and ADR 0029's Limits (docs/adr/0029-release-distribution.md:59) already names the staged file that answers a very high version. What changes is the reach: every person's command, not only `install`, now executes that file (once for `--version`, once for the hand-over). ADR 0030's limits should say this in one sentence.
- (3) Advisory, strongly suggested: `reconcile` does nothing when the effective user is root or when `<data dir>/bin` is not owned by the effective user. macOS `sudo` keeps `HOME`, so `sudo wizardingcode-mem status` from a channel copy would run a user-writable file as root, or leave a root-owned binary (and, when `bin` is missing, a root-owned folder) in the person's data directory that the plugins' scripts can no longer replace. `install` has this today; this item widens it to every command.
- (3) `WIZARDINGCODE_MEM_HANDED` is a loop guard, not a permission: setting it by hand only turns `reconcile` off, which leaves today's behaviour (an older copy may meet `SchemaTooNewError`). Fine. Say in the spec that the staged binary does nothing in `reconcile` by the real-path rule alone, and that the variable is only the second barrier; consider removing it from the environment of what the handed-over command spawns, so it does not leak into an agent's shell.
- (3) `WIZARDINGCODE_HOME` / `WIZARDINGCODE_MEM_DATA_DIR` pointing elsewhere: whoever sets the person's environment already chooses what runs (`PATH`); no new reach. The developer's hazard is real though: a compiled `dist/` build with a raised version, run once without an isolated home, stages itself over the real staged binary. No switch turns `reconcile` off; the e2e tests and `scripts/proof/*` must always set the data directory, and the plan should say so.
- (3) Real paths: spec.md:75 says "real path"; `stageBinary` compares with `resolve`, not `realpath` (src/install/binary.ts:44). Compare `realpathSync` on both sides in `reconcile` (a data directory reached through a link, a `bin/wizardingcode-mem` that is itself a link to the Homebrew copy). `renameSync` replaces a link at the target and never writes through it, which is right; keep it.
- (3) The temporary name `<target>.<pid>.new`: `copyFileSync` writes through an existing link at that name (src/install/binary.ts:52). Inside a 0700 folder this needs the same access as replacing the binary, so no new reach; still, remove the name first or copy with `COPYFILE_EXCL`, and have the day-old cleanup match only `<target>.<digits>.new`, use `lstat`, and unlink (never follow). A recycled pid inside a day is covered by the same remove-first.
- (3) The definition of a person's command (spec.md:5) includes `uninstall` and `backup --restore`: a newer copy stages itself before removing or restoring. Not a security fault; the build should decide it knowingly. `--version`, `--help` and an unknown command return before `reconcile` (src/cli/main.ts:54-66), which also keeps `stagedVersion` from recursing; keep that order, and decide whether `reconcile` runs before or after the legacy migration at src/cli/main.ts:68.
- (4) Nothing of the self-replacement is left half-open: nothing reads `update.json` to download or execute, `CHANNEL_COMMANDS` is a constant, and the non-goal (spec.md:24) and the findings rows (spec.md:90) record the deferral with its four blockers. ADR 0030 should carry one sentence for the later item: `latest` in `update.json` is a notice, obtained without authentication of the release's content, and must never by itself trigger a download; ADR 0029's limit on unsigned assets (docs/adr/0029-release-distribution.md:53) still stands.
