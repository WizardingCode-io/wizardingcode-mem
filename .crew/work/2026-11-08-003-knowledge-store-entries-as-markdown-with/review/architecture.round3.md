## Findings
- F-1 · advisory · src/modules/knowledge/repo.ts:32 · Carried from round two: the two function-level import cycles are still there. repo.ts imports resolve.ts (`projectAliasesOf`, `resolveRepo`) and resolve.ts imports repo.ts. repo.ts:29 imports author.ts and author.ts imports `gitUserName` from repo.ts. This commit widens the first cycle again: resolve.ts:10-17 now also takes `isDirectory` from repo.ts. The cycles are safe at runtime (rubric Q6, dependency direction). The fix is the one schema.ts already shows: move the path, manifest, foreign-folder and `isDirectory` helpers and `gitUserName` into a leaf that the three files share.
- F-2 · advisory · src/doctor/checks.ts:612 · The doctor still builds a `KnowledgeStore` by hand with `db: db as Db` (checks.ts:612-622). It also still lists the folders itself with hard-coded `knowledge/<scope>` and `knowledge/projects` paths (checks.ts:577-598) instead of `repoFolder`. Round two's boundary effect is closed: `refuseForeign` now runs at checks.ts:735 before the manifest read and `readRepoFiles` (:778), and `checkRepoConfig` runs at :789 before `statusOf`, the same order `openRepo` uses (repo.ts:706, 716). The remaining drift is that the doctor copies openRepo's guard sequence by hand. The amended CLAUDE.md:22 says "`openRepo` is the one way to a repository", and so does spec.md:130, which names `doctor` among its callers. Against that, spec.md:268 tells the doctor to read "by hand", so the Design contradicts itself here, and the code follows the Doctor section. A guard later added to `openRepo` would miss the doctor. This commit also makes `isDirectory`, a generic filesystem helper, a public export of the module's repository file (repo.ts:110-111) so that the core doctor can import it (checks.ts:35). The fix: give the doctor one exported read-only guard from the module (`refuseForeign` plus `checkRepoConfig`), or note the exception in CLAUDE.md:22.
- F-3 · advisory · .crew/work/2026-11-08-003-knowledge-store-entries-as-markdown-with/spec.md:130 · The spec's Design is still not amended, and this commit adds more departures from it:
  - spec.md:130 describes a refusal list (`include`, `includeIf`, `filter`, `hooksPath`, `fsmonitor`, `sshCommand`). The code now has an allow list, `ALLOWED_SETTINGS`, in repo.ts, plus a line-grammar parser.
  - spec.md:128 lists `-c` settings without the new submodule and init-format ones.
  - Several rules are absent from the Design: the `.gitmodules` refusal and the nested-repository rule, the `ownPath` and `INTENT_OPERATIONS` validation of the intent record, and kept bytes going back only to files directly under `entries/`.

  None of these crosses a boundary. ADR 0024:3 now says "Where this record and that specification differ, this record is the later one", which settles which text wins, and the ADR records each rule (ADR 0024:79-84, 100, 114). Amending spec.md would keep the later parts from building on the superseded text.
- F-4 · advisory · docs/adr/0024-knowledge-module.md:78 · The ADR's list of `-c` settings ("signing, hooks, fsmonitor, the untracked cache, the pager, external diff and the ssh command") does not name `diff.ignoreSubmodules=all` or `submodule.recurse=false`, which repo.ts now adds to `configArgs` (patch lines 278-280). ADR 0024:84 names only the `--ignore-submodules=all` flag on `git status`, so these two settings have no line in the record. Add them to line 78 or to line 84.
