## Findings
- F-1 · advisory · src/modules/knowledge/repo.ts:31 · Carried from round three, unchanged. Two function-level import cycles remain: repo.ts↔resolve.ts (repo.ts:31; resolve.ts also takes `isDirectory`) and repo.ts↔author.ts (repo.ts:28; author.ts takes `gitUserName`). Neither breaks at runtime (rubric Q6, dependency direction). The fix is the same as before: move the path, manifest and folder helpers and `gitUserName` into a leaf module, as schema.ts already does. This commit adds no new cycle; index-store.ts importing `isDirectory` from repo.ts follows the existing direction.
- F-2 · advisory · src/modules/knowledge/index-store.ts:564 · The rule "this error is a repository's refusal, not a fault" is written twice, in two layers: inline here, and as `isRefusal` at src/cli/commands/knowledge.ts:224-225, which the CLI also applies around `adopt()` (knowledge.ts:193-196). Both key on the generic code `"invalid"`. The module uses that same code for invalid input as well (store.ts:100 `invalid = (message) => new KnowledgeError("invalid", …)`), and for a path reached through a link in `undoStaged`. So the CLI, not the store, decides what counts as "one repository refused". Any future `invalid` raised mid-adopt, or mid-open for a reason other than the repository's state, would be printed as a refused repository with exit 1 instead of stopping the command. This stays within the contract: errors.ts:12 says "The code is what a caller branches on", and ADR 0024:92 records the behaviour (go on, say it on stderr, exit 1). So it is a convention point, not a boundary crossed (Q3/Q6). The fix: export one predicate from the module (or give refusals a code of their own) and use it in both places.
- F-3 · advisory · .crew/work/2026-11-08-003-knowledge-store-entries-as-markdown-with/spec.md:130 · Carried: spec.md's Design is still not amended, and this commit moves the code further from it. spec.md still describes the support folders the code no longer has (a template folder, a no-hooks folder and an empty configuration file under `knowledge/`). ADR 0024:3 says the ADR is the later text, and the ADR records each of these, so nothing crosses a boundary. Amending spec.md would keep parts 2 to 4, which build on it, off the superseded text.
