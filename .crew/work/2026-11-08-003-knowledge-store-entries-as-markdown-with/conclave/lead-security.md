# security lead's validation of 2026-11-08-003: spec
verdict: returned
## Returns
- R-1 · spec.md:102 (and :103, AC-2 at :237) · The git isolation covers the global and system configuration and `core.hooksPath`, but not the repository's own `.git/config`. Git reads that file on every call. A `core.fsmonitor`, `core.sshCommand`, `diff.external` or `core.pager` value there runs a command or changes behaviour on `git status`, which the dirty check, `adopt`, `rebuild` and `doctor` all call. A folder under `knowledge/projects/*` that `resolveRepo` adopts through its manifest (:94), or a repository a person or a later sync part drops in, can carry such a config. Line 103 says "Nothing of the person's git setup (fsmonitor … includes) runs here", and that claim does not hold for the local config. The runner must add `-c core.fsmonitor=false -c core.untrackedCache=false -c core.pager=cat -c diff.external=` (or an equivalent). `resolveRepo` and `ensureRepo` must also refuse, or reset, a repository whose local config sets `core.fsmonitor`, `core.sshCommand`, `core.hooksPath`, `include.path` or `includeIf`. AC-2 needs a case where a local `.git/config` sets `core.fsmonitor` to a marker-writing command and the marker is not written. This must also reconcile with the plan's timeout test (plan.md:19), which uses `-c core.fsmonitor=sleep` and would then need a stub `git` instead.
- R-2 · spec.md:155 (`acceptProposal` / `rejectProposal`), with :132 · The proposal id has no stated format or validation. It reaches the file system (`proposals/open/<id>.md`, `git mv` to `decided/`) and git arguments from a caller-supplied value in `acceptProposal(store, ref, proposalId, person)`. The text at :267 says "file names are validated slugs, nothing with a separator or a dot reaches the file system", but that covers slugs only. The same gap applies to the `entry` and `id` values read back from the proposal's frontmatter, since a hand-edited proposal can carry any string. The spec must state that the proposal id and the entry id are UUIDs (pattern `UUID`, plan.md:8). Both operations must refuse a non-matching id with code `invalid` before any path is built. AC-5 needs a case with `../x` and `a/b` as proposal ids.
- R-3 · spec.md:132 and AC-5 at :240 · Content written by an agent is not redacted. An agent's proposal body and fields come from a session, and the proposal is committed to git history, which the engine never rewrites ("Nothing is deleted from the repository", :155). Parts 4 to 6 then share it. A secret pasted into a proposal stays in history even after a person rejects it. The project already has `src/core/redact.ts` for this, and the log path redacts. The spec neither applies it at the agent write nor records a decision not to. It must either (a) pass an agent writer's title, context, subject and body through `redact` before the proposal file is written, with AC-5 gaining a case where a token-shaped string in a proposal body is stored redacted, or (b) record a ruling in the ADR (AC-12) that content is stored verbatim, with the reason and the later part that adds a scan. A person's write is deliberate and can stay verbatim.
## Notes
- The git spawn is otherwise well bounded. It uses an explicit `--git-dir`/`--work-tree`, `GIT_CEILING_DIRECTORIES`, a blanked global configuration, `GIT_CONFIG_NOSYSTEM`, `hooksPath` pointed at an empty folder, signing off, `HOME` not passed, a 15 s kill, and `--` before paths (spec.md:100-106). AC-2 and AC-8 name tests for the global hook, the parent repository and the timeout.
- Commit identity is safe. Names are 1 to 80 characters with no newline and never start with `agent:`. Agent ids match `^[a-z0-9][a-z0-9-]*$`. E-mails use the reserved `.invalid` domain (:126). The settings validation refuses `agent:` names (AC-9). The guarantee's boundary for an agent with shell access is stated honestly (:128, :261).
- File safety matches ADR 0020's Safety section. It covers `O_NOFOLLOW` on read, `lstat` refusal on write, a 256 KiB cap, a 5,000-file cap, a validated slug, a temp-file rename, folders at 0700 and the `.git` directory check (:104, :202, :267, AC-13). Two things are not explicit: whether the `entries/` and `proposals/` directories themselves are `lstat`-checked, and a FIFO refusal (ADR 0020 uses `O_NONBLOCK` plus `fstat`). Neither is a return, since the same open helper can cover them, but the implementer should mirror ADR 0020.
- The data-migration risk is covered. The module namespace is separate and `user_version` stays at 7 (:186). Version 6 drops only the withdrawn module's objects (:194). Too-new handling is explicit (:191). The rollback is stated (:259). AC-3 tests the archived-shape case and concurrent opens (plan.md:12). Backing up before a migration when a module already had tables is stated (:189).
- Logging uses `logError` under `knowledge.<operation>` with git's stderr clipped to 300 characters (:106, AC-13). `src/util/log.ts` already redacts, per the codebase review at `spec-review/brainstorm-goldfish-codebase.md:20`.
- The author's name in commits stays inside the data directory and nothing leaves the machine in this part (:260).
