### Blocker

- `goldfish-design` design-1.7-1 · spec.md:112, :124, :157 (rollback on a failed commit) · The spec says each staged path is "restored from HEAD (`git checkout -- <paths>`)". That is not what the command does. `git checkout -- <path>` restores the working tree from the index, and the index holds the content that `git add` just staged, so the command does nothing. A new file's staged add also stays in the index after the file is removed. The result is the opposite of what is promised. After a failed write, accept or reject, the failed content is still on disk and staged, `git status --porcelain` reports the path as dirty, and the next write is refused as `dirty`. `knowledge adopt` would then commit the failed agent or person content as the person's hand edit. A failed accept therefore does not leave the proposal "back under `open/` unchanged". The command needs to be `git checkout HEAD -- <paths>` (or `git restore --source=HEAD --staged --worktree`), with the index entries of new paths removed. AC-18 (line 252) tests the outcome, but whoever builds it will copy the wrong command from the spec.
  - propose-fix: Right: after git add, checkout from the index restores the staged content, so nothing is recovered. Fix: a failed commit is undone with git restore (source HEAD, staged and worktree) for the paths that existed at HEAD, and with git rm cached plus file removal for paths that did not; the recovery is proven by an empty git status for those paths in AC-18's test; the spec and the plan name the commands.

- `goldfish-design` design-1.7-2 · spec.md:118, :231, :260 (the lease) · Line 231 rejects a lock file because "an age-only lock can be stolen from a live writer". The lease has the same flaw. `claimLease` (src/store/meta.ts:64-65, 73-86) treats a lease as free once `until <= now`, even if its owner is still alive, and Risks (line 260) admits "of a live one after 60 s". Nothing renews the lease. The worst case is longer than 60 s: a project write that first creates the workspace repository (init, add, commit), then the project repository, then runs status, add and commit is about nine git calls with a 15 s timeout each. Adopt and `removeArea`, which runs `ensureFresh` over every repository, have no bound at all. So a slow but live writer can lose its lease halfway through, and a second writer can then run at the same time on the same work tree and index. The spec needs either renewal at each git step or a bound proven to fit within 60 s.
  - propose-fix: Right: an unrenewed lease can expire under a live writer. Fix: the lease is renewed (claimLease by the same owner extends it) before every git call, and a renewal that fails aborts the operation before that call; with each git call bounded at 15 s, a lease can never be lost between a renewal and the call it protects.
