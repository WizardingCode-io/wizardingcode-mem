## Findings
- F-1 · Major · spec.md:251-252, Acceptance criteria (AC-14 and AC-18) · AC-14 is still in the list, marked "superseded by AC-18", and AC-18 sits between AC-14 and AC-15, so the numbers run out of order. The two criteria disagree on adopt. AC-14 says a failed adopt commit restores every staged path from HEAD. AC-18 and the design (lines 112, 161) say the paths are unstaged and the original bytes written back. Someone writing tests from the AC list could implement AC-14 as written, and a failed adopt would then delete the person's hand edits. The list should hold one criterion for this.
- F-2 · Major · spec.md:141, Proposals code block · The template line `base_version: 2          # 0 for a new entry` has a comment at the end of the line. The parser rule at line 80 counts `#` as a comment only at the start of a line. A renderer or test fixture copied from this template would produce a `base_version` value that is not a whole number, and the file would be indexed with a problem. The note belongs in the prose, not inside the template.

Here the alternatives are a third-level subsection inside Design, not their own section. The content is there and is substantial, but the name and level don't match the rubric's section list.
