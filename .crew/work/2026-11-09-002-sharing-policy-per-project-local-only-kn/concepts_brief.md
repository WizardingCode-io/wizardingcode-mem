# Concepts brief: the sharing policy

## Overview

Before any team server exists, the person decides what may leave this machine: a level per project (`local`, `knowledge`, `all`; shown as Nothing, Knowledge, Knowledge and memories), which knowledge roots may leave (the workspace repository, the shared repository), and which knowledge areas of each root are shared. One pure function in `src/sharing/policy.ts` answers, for one destination and one item, `send`, `withdraw` or `keep`, with the reason; the team server and the sync client (parts 5 and 6) call it and nothing else decides. Every default is local. The choices live in the `sharing` schema namespace of the database (levels per project and destination, the ledger, the change log) and in two keys of `<data dir>/env` (the roots and the areas), the viewer sets all of them, and `status`, `doctor` and `wizardingcode-mem share` print what the policy would let out. The concept (`concept.md`) went to six reviewers in brainstorm mode (`spec-review/brainstorm-goldfish-*.md`); this brief is the concept after them.

## Analysis

**A core migration 8 breaks the rollback parts 1 and 2 promised.** Raising `user_version` to 8 makes every 0.6.0 binary refuse the database (`SchemaTooNewError`, `src/store/db.ts`), on every hook, without a sound; parts 1 and 2 built the module migration namespace so that `user_version` stays 7 and 0.6.0 ignores the new tables (zoom-out, design, readiness, codebase, structural). The levels move to a `sharing` namespace registered in part 1's `MODULE_SCHEMAS` (`src/engine/module-schemas.ts`), with no foreign key to core tables: a missing row means `local`, a level is added without rebuilding `projects` (the `CHECK` lives in code), `status` and `doctor` on an older store treat a missing table as "everything local", and a v7 backup restored by the new binary starts local.

**One place can go to several places.** The concept assumed one server. A level stored per project alone would send one client's knowledge to every destination a later part configures, which ADR 0018 calls the worst failure the product can have, and a predicate without a destination argument cannot be fixed once data has left (structural, design). The level is keyed by `(project, destination)`; this part has one destination, `team`, which part 5 binds to the one server the mission describes; a second destination starts with every level local; the predicate takes the destination and answers `keep` for an unknown one.

**The unit that leaves is an item's current content, never a repository.** Part 1 keeps every version, decided proposals and old private-area content in git history, and names `base_hash` "for the sync". A per-entry predicate cannot be enforced over a `git push` (design, zoom-out, comprehension). This part fixes the rule for parts 5 and 6: what leaves is the exported current content of one allowed entry or one allowed memory, plus the metadata named below; git history, proposals, drafts and archived entries never leave; the sync reads the bytes it sends after `ensureFresh` and a clean status, never a stale index row (design).

**"May leave" is too little an answer.** Lowering a level recalls nothing; the sync needs to tell "never shared" from "shared, now withdrawn", and revocation needs a record of what left, when, to where, at which version (structural, design, codebase). The predicate returns `send`, `withdraw` or `keep` with a reason code, reading the ledger record the caller passes for the item; `sharing_ledger(destination, item_kind, item_uid, direction, version, hash, policy_epoch, at, withdrawn_at)` is created here and written by parts 5 and 6; an item received from a destination (`direction = received`) is never sent to another, and never back. A memory's `item_uid` is its row id on this machine (memories are never deleted, so ids are never reused; the device token of part 5 scopes it); an entry's is part 1's UUID.

**Memories ignore areas, and `all` needs a fixed meaning.** Memories have no area, so a project at `all` sends finance talk whatever the area list says; the selector must say so. Memories also carry `stale`, `scope = 'branch'` and `origin = 'imported'`, which the concept left unsaid (comprehension, design, structural, readiness). `all` means exactly: status `active`, `stale = 0`, `scope = 'project'`, `origin` not `imported`, and not one of the author's rules (`isUserMemory`, `src/store/links.ts`). ADR 0025 records the set; a level with a different meaning is a new name, so what left under `all` is never reinterpreted.

**One flat list of area ids switches two taxonomies at once.** Part 1's D-9 gives the workspace and the shared repository separate taxonomies (comprehension, zoom-out, design, structural, readiness). Area ids are root-qualified in the setting (`workspace:sales`, `shared:sales`); the workspace's ids govern the workspace and every project repository, which are rooted on its taxonomy. The roots themselves are a list too (`WIZARDINGCODE_MEM_SHARE_ROOTS`, default empty), so the shared repository is no longer "always": it leaves when the person names it, like the workspace, and the viewer shows beside each control how many entries it releases, so the AND of a root switch, an area and a project level is visible before the click (comprehension).

**The environment must never widen sharing.** `loadSettings` lets the environment win over the file, so one exported variable in a shell profile, a host's MCP env block or direnv shares from that process only, and the viewer's switch cannot turn it off (zoom-out, design, structural, readiness, codebase). For the two sharing keys the file is the policy; an environment value is honoured only when it narrows (an empty or shorter list), and `doctor` warns when one was ignored.

**Loading fails closed.** `loadSettings` does not apply `RULES` to a hand-edited file; a lenient parser turns a typo into egress; the loader can meet a missing table, an unreadable file or a too-new module schema (design, readiness, codebase). Any failure to load gives a policy where nothing leaves, logged once; one invalid token empties the whole area list and `doctor` names it; an id not in its root's current taxonomy is inert and `doctor` warns, and the viewer's save drops it (so a removed area does not re-arm when re-added, once anyone has saved). `WIZARDINGCODE_MEM_SHARE_ROOTS` and `WIZARDINGCODE_MEM_SHARE_AREAS` are parsed as `moduleList` is: trimmed, lower-cased, de-duplicated, every token checked.

**A project's level must follow the project's identity.** Teammates and the server match a project only by its `remote:` alias (the Collaboration card says so today); adoption of an `imported:` project, a folder reused by another repository, and `knowledge_repos` adoption or remap can hand a level to data the person never meant (structural, design, readiness). A level above `local` can be set only on a project with a `remote:` alias and is bound to it; when the project no longer carries that alias the predicate answers `local` and `doctor` warns; a disabled project is `local` (no production path sets `disabled`, so the "re-enable" moment does not exist and no doctor warning covers it, as the codebase and zoom-out lenses found); a project repository mapped to project 0, an orphan or an ambiguous manifest answers `local`. A folder reused by a repository without a remote keeps the old project id today (ADR 0018's rule); the ADR names this limit.

**Restores and moves.** `backup --restore` swaps the database and not `<data dir>/env`, so an old copy could bring back a level the person lowered (comprehension, design, readiness). Restore resets every level to `local` and writes one change-log row with source `restore`; the roots and the areas keep their current values; `move` carries everything untouched. Both are stated in the ADR.

**Every change is recorded, and widening asks first.** Nothing logged a level change, and every host gives agents a shell, so `share project all` from an agent is consent forgery (design, codebase, comprehension). `sharing_changes(id, at, source, what, old, new)` records every change with its source (viewer, CLI, restore); `sharing.epoch` in meta grows on every change, the predicate returns it, the ledger records it, and the sync re-reads the policy at every batch and stops when the epoch moved; the viewer confirms a widening with the counts it releases, the CLI asks on a TTY or needs `--yes`; `share status` prints the last change. The boundary stays part 1's: an agent with a shell can still do it, and the log is how a person finds out.

**The viewer already made a promise.** `ui/src/components/settings/Team.vue` ("Collaborative mode", marked soon) says sharing is opt-in per project, that anything inside a `<private>` block never leaves, and that "this page becomes the switch" (zoom-out, codebase, comprehension). That page becomes the Sharing page: the roots, the areas as toggles with the count each releases (locked with "Set by the environment" when the environment narrowed them), the count of projects per level with a link to Across projects, and plain statements: the policy governs the team server only (TypeSafe judgements are governed by the key, as README Privacy says), memories have no area, new areas start private, a lowered level recalls nothing already sent, and the first sync sends everything allowed with no further prompt. No part numbers in product text. The `<private>` promise holds because every text that leaves passes `redact` at the edge (`[PRIVATE]`, `src/core/redact.ts`), named here as a required step of the contract parts 5 and 6 implement. Across projects: each row shows its level, the project dock sets it with the confirmation; a project without a remote shows why it cannot be set.

**What rides along, and what never leaves.** The concept covered entries and memories and nothing else (design). With an allowed entry: its current frontmatter and body, its scope and its project's `remote:` alias. With an allowed memory: redacted title and body, kind, importance, status, created and updated times, the project's `remote:` alias. Never: turns, sessions, the history index, `hook_runs`, `injections`, `memory_files` paths, `terms`, `branch`, `commit_sha`, `transcript_path`, local `path:` and `gitdir:` aliases, the project `key`, commit e-mails. Redaction at the edge is the second required step.

**Read-outs without a reader.** Three read-outs of counts nobody consumes yet, counted over the whole store, repeat each other (zoom-out, design, codebase, comprehension). Kept: a `sharing` line in `status` for the current project (its level, the roots, the shared areas, the entries and memories of this project that would leave), the viewer's counts through `GET /api/sharing`, and one CLI, `share`, with `project <level> [--yes]`, `roots <list>`, `areas <list>`, `status [--list]` (the items, not only counts) and `explain <scope>/<slug> | memory <id>` (the predicate's reason). Counts come from the knowledge index after `ensureFresh` and from `memories` by the `memories_rank` index, never on the hook path. `doctor` is `ok` with the policy's summary and warns only for an invalid raw value, an ignored environment value, a level whose alias the project lost, and an inert area id; "sharing configured but no team" is not a warning.

**Not taken, with the reason.** Building only the stored choices and leaving the predicate to part 5 (zoom-out): the brief's acceptance is that parts 5 and 6 call one predicate and nothing else decides, and its contract (destination, three answers, ledger, provenance, redaction) is what those parts must build against; writing it here, with tests, is how the contract is fixed before any data leaves. A `uid` column on `memories` (structural): a core migration; the row id is stable on this machine because memories are never deleted, and the device token scopes it. Dropping ids from the list inside part 1's `removeArea` (structural, design): a cross-part coupling; inert-at-load plus drop-on-save covers it. Sharing the author's rules (concept): a later part.

## Goals vs. Non-Goals

Goals: the `sharing` schema namespace (levels per project and destination, the ledger, the change log); the two env keys with narrow-only environment and fail-closed parsing; the predicate with three answers, reasons and the epoch; the fixed meaning of `all`; the identity rule (remote alias, disabled, orphans, restore); the Sharing page in place of the Collaboration card and the level in Across projects; `share`, the `status` line, `doctor`, `GET /api/sharing`; ADR 0025; pinned snapshots unchanged.

Non-goals: the server, the sync, any network (parts 5 and 6); redaction's implementation at the edge (part 6 applies `redact`); sharing the author's rules; a per-entry override; a second destination; deleting anything.

## Alternatives Weighed

- A column on `projects` by core migration 8: rejected; it breaks 0.6.0's rollback and pins the enum in a `CHECK` that only a table rebuild can widen.
- A level per project alone: rejected; one choice would reach every destination a later part adds.
- Syncing repositories by `git push`: rejected for parts 5 and 6; history and proposals would carry private content past the predicate.
- A boolean predicate: rejected; the sync needs `withdraw`, and the reason is what a person asks at 3 AM.
- One flat area list: rejected; two taxonomies, one id, two meanings.
- The shared repository always shared: rejected; nothing leaves until named, and the shared repository has a switch like the workspace.
- Environment wins (the settings rule): rejected for the sharing keys; a stray variable would widen from one process only.
- A `uid` column on `memories`: rejected; a core migration for an id that is already stable on this machine.
- Storing the levels in the env file: rejected; the project list is in the database and the viewer edits rows.
- A doctor warning for "sharing configured but no team": rejected; a permanent badge with no fix.

## Key Decisions

D-2 (everything local), D-3 (a list of shared areas), D-4 (the author's rules never leave) as recorded; D-1, D-5, D-6 and D-7 superseded in part by D-8, D-12, D-15 and D-18:

- D-8: the levels live in the `sharing` schema namespace of `module_migrations`, `user_version` stays 7, no foreign keys, a missing row is `local` (supersedes D-1's column and core migration 8).
- D-9: a level is keyed by `(project, destination)`; one destination, `team`, in this part; the predicate takes the destination and an unknown one is `keep`.
- D-10: what leaves is the current content of one allowed item; never git history, proposals, drafts or archived entries; the sync reads the bytes it sends after `ensureFresh` and a clean status.
- D-11: the predicate answers `send`, `withdraw` or `keep` with a reason code and the epoch, reading the ledger record the caller passes; `sharing_ledger` is created here and written by parts 5 and 6; a received item never goes to another destination.
- D-12: area ids are root-qualified; the roots that may leave are a list (`WIZARDINGCODE_MEM_SHARE_ROOTS`, default empty); the shared repository leaves only when named (supersedes D-5's "always" clause; its area rule stands).
- D-13: the environment never widens the two sharing keys; a value is honoured only when it narrows; `doctor` warns when one was ignored.
- D-14: loading fails closed: any failure means nothing leaves; one invalid token empties the area list; an id not in its root's taxonomy is inert and dropped at the viewer's next save.
- D-15: `all` means active, not stale, project scope, not imported, not a user rule; the set is fixed in ADR 0025 and a different set is a new level name (supersedes D-6's "every active memory").
- D-16: a level above `local` needs the project's `remote:` alias and is bound to it; a lost alias, a disabled project, project 0, an orphan or an ambiguous manifest answer `local`; restore resets every level to `local` and logs it; `move` keeps them.
- D-17: every change is recorded in `sharing_changes` with its source; `sharing.epoch` grows on every change; widening asks for confirmation in the viewer and on the CLI (`--yes`).
- D-18: the Collaboration card becomes the Sharing page, with the counts each control releases and the plain statements above; product text carries no part numbers (supersedes D-7's separate card).
- D-19: the metadata that accompanies an allowed item and the list of what never leaves are fixed here; redaction at the edge is a required step of the contract.
- D-20: the read-outs are the `status` line for the current project, `GET /api/sharing`, and `share` (`project`, `roots`, `areas`, `status [--list]`, `explain`); counts never run on the hook path; `doctor` warns for invalid, ignored, unbound and inert only.
