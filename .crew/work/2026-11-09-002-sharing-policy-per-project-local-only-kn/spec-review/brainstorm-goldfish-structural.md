## Findings
- F-1 · Blocker · Design sketch, The policy (`projectLevel`, `workspaceKnowledge`, `sharedAreas`) · The policy assumes there is only one place data can go. Once part 5 has several teams or clients, a project set to `knowledge` goes to every team configured, so one client's knowledge reaches another client's server. ADR 0018 calls that "the worst failure this feature can have". The concept should store the level per (project, destination) now, with no destinations in this part and every lookup falling back to `local`, rather than add a destination dimension once data has already left.
- F-2 · Blocker · Design sketch, `mayShareEntry(policy, {...})` / `mayShareMemory(policy, {...})` · The predicate's signature has no destination argument. Adding one later changes every call site in parts 5 and 6, and while that change is half done, a missing argument could quietly mean "any destination". Fix the signature now as `mayShare(policy, destination, item)`, and make an unknown destination answer false.
- F-3 · Blocker · Not in this part / whole concept · Nothing records what left, when, to which destination, or at which version/hash. Revocation can't be built without it: when a project goes from `all` to `local`, an area becomes private, or an entry is archived, the predicate only says "do not send". Nobody knows which server copies to withdraw. Reserve the table now, e.g. `sharing_ledger(destination, item_kind, item_uid, version, hash, policy_epoch, sent_at, withdrawn_at)`, even if this part writes nothing to it.
- F-4 · Major · Design sketch, The policy (boolean answer) · A yes/no "may leave" is too little for the sync. For each item it needs one of three answers: send, withdraw, or leave alone. Otherwise each sync part derives "withdraw" itself by comparing the ledger with the predicate, which breaks the brief's rule that the predicate is the one place that decides. Fix the return type now, even if this part only ever produces send or leave alone.
- F-5 · Major · Design sketch, `mayShareMemory` (memories keyed by `memories.id INTEGER`) · Entries have UUIDs (part 1 D-8), but memories only have a local row id, and SQLite can reuse a deleted id (part 2 says so for `knowledge_shown`). If a memory leaves under its row id, the server holds keys that collide across machines, and later updates or withdrawals can't find the right row. The policy part should require a stable `uid` on memories before any memory can be `all`, or state that memory sharing waits for one.
- F-6 · Major · Design sketch, the predicate's inputs (`scope`, `projectId`) · The inputs carry no provenance, so a teammate's memory or entry that arrives on this machine is judged like local data. A project set to `all` would send team A's data on to team B. The item needs an origin (local, or received from destination X). Received items should never go to a destination other than the one they came from, and that rule belongs in the predicate.
- F-7 · Major · Design sketch, the shared scope rule ("the shared scope always (it is the team's)") · Part 1 has exactly one `shared/` repository (`UNIQUE (scope, project_id)` with project_id 0), and the concept treats it as "the team's". Several teams need one shared repository each. The predicate's rule "shared scope always leaves" then becomes wrong (to which team?), as does the single shared taxonomy the area toggles list. The concept should state that the shared scope belongs to one destination, or say this is unresolved and needs part 1's scope key widened.
- F-8 · Major · Storage, `WIZARDINGCODE_MEM_SHARE_AREAS` · Area ids are unique only within one taxonomy, and part 1 D-9 gives the workspace and the shared repository separate taxonomies. A flat set of strings shares `sales` from both, even if the two roots mean different things by it. The setting can't later tell them apart without a format change. Qualify the ids now as `<root>:<area>`, or say why one namespace is intended.
- F-9 · Major · Storage, migration 8 `CHECK (sharing IN ('local','knowledge','all'))` · A CHECK constraint on `projects` can only be widened by rebuilding the table. That table has foreign keys from sessions, turns, memories and aliases, and ADR 0018 P1 avoided exactly such a rebuild. The enum will need values (memories by kind, user rules, memories without knowledge). Put the level in its own table keyed by project (and destination, F-1) with the check in code, so values can be added without a migration.
- F-10 · Major · Storage / The policy (`local < knowledge < all`) · The three levels force an order: you can't share memories without knowledge, decisions without gotchas, or one linked product without the other. Once data has left under one meaning of `all`, a later split ("does old `all` include user rules?") has to reinterpret what already went out. Record the meaning of each level in ADR 0025 as a fixed set of flags, so new levels are new names and existing ones never change meaning.
- F-11 · Major · Storage, settings ("the environment wins over the file") · The workspace switch and area list follow the settings rule that the environment wins over the file. A sync daemon started from a shell with `WIZARDINGCODE_MEM_SHARE_AREAS` set would share more than the viewer shows, and nothing would record it. Any key that widens sharing should be read from the file only, or the environment should only be allowed to narrow it.
- F-12 · Major · The policy ("loaded once per call site") · The loaded policy has no version or epoch. A long sync run keeps using a policy the person has since narrowed, and nothing tells the sync which policy an item left under. Give the policy a monotonic `policy_epoch` (in `meta`), bumped on every change. The predicate returns it, the ledger records it (F-3), and a narrowing interrupts a run already going.
- F-13 · Major · The policy ("A disabled project is `local` whatever its column says") · The stored level is kept while a project is disabled and comes back silently when it is turned on again. A project disabled for privacy then starts sharing again with no confirmation. Either reset the level to `local` when the project is disabled, or make re-enabling show the level it brings back and log that as a widening.
- F-14 · Major · Design sketch (no project identity) · The server and teammates can only match a project by a stable identity, the `remote:` alias. `projects.id` is local, and a project with only `path:`/`gitdir:` aliases has no identity across machines. The concept should state that a project with no `remote:` alias can be set to `knowledge`/`all` but can't be matched by teammates, and `doctor` should warn about it.
- F-15 · Major · Not in this part ("redaction at the edge (part 6's)") · Redaction sits in part 6 while the predicate is "the one place that decides". So two components decide what text leaves, and they will drift apart. A person's entries are verbatim (part 1), so a person's own text could carry a key past a predicate that said yes. Either name redaction as a second required step of the predicate's contract, or make the predicate's result carry "must be redacted".
- F-16 · Nit · Storage, unknown area ids "kept and warned" · An area id that was removed and later added again with a different meaning starts sharing again automatically, because the stale id is still in the list. `doctor` warns only while the id is unknown, not once it exists again. Drop ids from the list when the area is removed, or tie each id to the taxonomy version it was enabled under.
- F-17 · Nit · The viewer and the CLI (level selector per project row, `share project <level>`) · A single selector per row and a CLI command with no destination will have to become a projects-by-destinations matrix and `share project <level> --to <team>`. Shaping the API now (`PUT /api/projects/<id>/sharing {destination?, level}`) avoids breaking the endpoint and the command in part 5.
- F-18 · Nit · Status and doctor (counts "that would leave") · The counts are of what would leave today. Once the sync exists the person also needs what has left and to where, which only the ledger (F-3) can answer. Name the `status` line's future second half now so its format doesn't change later.
