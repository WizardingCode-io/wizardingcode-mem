## Findings
- F-1 · advisory · src/ui/server.ts:13106 (diff line; also src/ui/api.ts `setProjectSharing`, diff line 13011) · When the policy fails to load, `PUT /api/settings` with a sharing key and `PUT /api/projects/<id>/sharing` now answer 409 with the policy's problem. The spec's route contract and ADR 0025 ("The read-outs", line 171) list no such status for the viewer's routes; they record the closed-policy refusal only for the `share` command (spec "The command"; ADR line 170). The behaviour matches the CLI and is safe. The fix is to add the 409 to the viewer bullet of ADR 0025 so parts 5 and 6 and the viewer read one route contract.
- F-2 · advisory · src/doctor/checks.ts:883 · The `sharing` check calls `loadPolicy`. When the load fails, `loadPolicy` calls `logError`, which runs `mkdirSync` on `<data dir>/logs` and appends a line. That runs inside `runChecks`, whose own contract says "Looks, and changes nothing: no directory, database or setting is created or altered". The spec does ask the loader to log once per process, so this is a convention clash, not a crossed boundary. The fix is to have doctor take the closed policy without logging (for example through an option on `loadPolicy`, or a reader that does not log).
- F-3 · advisory · CLAUDE.md:10 · The new sharing bullet lists the module's files one by one but leaves out `hash.ts` (`memoryHash`, a pinned part of the contract) and `migrations.ts` (`SHARING_MODULE`, the generation key). ADR 0025 names `MEMORY_HASH_FIELDS` but not the file. Naming the two keeps the map complete for the next reader.
- F-4 · advisory · ui/src/api.ts:31902 · The viewer's `Project.remote` doc says "It has a git remote". The server contract it mirrors (`ProjectSummary.remote`, src/ui/api.ts diff line 12806) is narrower: "a host-led git remote (`isHostLedAlias`)", and a local-path or `file://` remote is none. The hand copy's comment should say the same so the dock's disabled sentence is read correctly.
