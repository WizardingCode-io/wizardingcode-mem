## Findings
- F-1 · defect · src/ui/api.ts:86 · `listProjects` decides `remote` with `alias LIKE 'remote:%'`, a second copy of the rule "this project has a name a team knows it by". That copy disagrees with `isHostLedAlias`, which `setLevel` applies (AC-20). For a project whose only remote is a path or `file://`, the dock enables the level control (ui/src/components/ProjectsView.vue:118) and hides the "no git remote" sentence. The server then answers 409 `no-remote`, and the person only sees "The level could not be saved." The docstring at src/ui/api.ts:61 also says this alias is "which a level is bound to", which is false for such a remote. Fails question 2 (logic duplicated, and the copies diverged) and question 6 (behaviour).
- F-2 · defect · src/sharing/report.ts:103 · `counterIn` decodes the epoch with a hard-coded `2 ** 20`. It repeats the layout that `epochOf` builds from the private `HASH_BITS` in src/sharing/levels.ts. If `HASH_BITS` changes, `withChange` silently computes wrong preview epochs. Fails question 2 (the epoch layout is written twice, not one call or one exported constant).
- F-3 · advisory · src/sharing/levels.ts:6 · The doc block "The destinations there are: the team's server, alone…" is orphaned. It sits above the `REMOTE_ALIAS` comment, so `REMOTE_ALIAS` has two doc blocks and `DESTINATIONS` (line 14) has none. Question 10/6.
- F-4 · advisory · src/sharing/levels.ts:112 · `policyWith` ("A hand-built policy, for tests") is a test fixture exported from a production module. `resetSharingLog` (src/sharing/policy.ts) and the forwarding re-export `export { GENERATION_KEY, newGeneration }` (src/sharing/store.ts:25) are the same kind: only tests import them through store.ts. Questions 5 and 8.
- F-5 · advisory · src/sharing/store.ts:42 · The two sharing key names are declared again in four places: store.ts:42-47 (with `SHARE_KEYS`), src/sharing/patch.ts:8, src/cli/commands/share.ts:153 (`LIST_KEYS`) and src/status/report.ts:170 (`SHARING_LISTS`). src/settings/settings.ts already exports `SHARING_KEYS` and `SharingKey`. Duplicated boilerplate, question 2.
- F-6 · advisory · src/sharing/report.ts:162 · `rootOf` repeats the expression `item.scope === "shared" ? "shared" : "workspace"` that `entryRefusal` writes inline in src/sharing/policy.ts. This is the rule "whose areas govern an entry", written twice. Question 2 (one line).
- F-7 · advisory · src/sharing/report.ts:93 · `knowledgeReadable` adds `hasTable(db, "knowledge_repos")` after `moduleSchemaState(...) === "current"`. `readStore` (src/sharing/policy.ts) likewise asks `hasLevelsTable` before trusting the schema state. Both guards exist because `moduleSchemaState` answers `current` for a store with no `module_migrations` table. AC-3 calls that state "behind". The cause is worked around in two readers instead of being fixed in one place. Question 9; documented, so advisory.
- F-8 · advisory · ui/src/components/settings/Sharing.vue:120 · `save()` re-derives "does this patch widen" against the in-force lists. The server's `previewSettingsPatch` already decides this against the file's lists. If the two ever disagree, the server's 400 `needs-confirm` reaches the person as "The settings file could not be written." Question 2.
- F-9 · advisory · ui/src/api.ts:178 · `SharingReport`, `SharingChange`, `SharingView` and `PolicyChange` restate by hand the server's `Report`, `ChangeRow`, `SharingView` and `PolicyChange`. The same file already imports types from ../../src/sharing/types.ts, and type-only imports from report.ts/store.ts would cost no bundle. These copies can drift. Question 2.
- F-10 · advisory · src/status/report.ts:194 · `sharingStatus` calls `publicSettings(env, dataDir)` only to learn which lists the environment narrowed. That parses the env file a second time, right after `loadPolicy` already parsed it and computed the lists. Question 5 (simplest thing).
- F-11 · advisory · src/cli/commands/install.ts:110 · `confirm` is now a layer that only forwards: `askYesNo(question, true)`. Question 5.
- F-12 · advisory · README.md:91 · "A project needs a git remote to be set above Nothing" leaves out the scope limit the code and ADR 0025 enforce: a remote that is a local path or a `file://` URL is refused. Question 11 (this is new prose, so no dropped fact, but the stated rule is wider than the real one).
