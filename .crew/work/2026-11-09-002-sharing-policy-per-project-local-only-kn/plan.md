# Plan: the sharing policy

Every task names its criterion and ends with a red or a green run. The test command for one file is `./node_modules/.bin/bun test <file>`; the full suite is `bun run test` at the gate. No implementation code here: shapes, cases and commands. Each phase leaves the tree buildable: `bun run typecheck` passes at the end of every phase, so no test file imports a module a later phase creates (the types and the levels leaf come first; the loader before the store's policy-reading writes). Tests create their data directory under `tmpdir()`, set `HOME` to a throwaway folder when they touch git, and pass their own `env` to `loadSettings`, `loadPolicy`, `statusReport`, `runChecks` and the CLI; `tests/preload.ts` deletes the two sharing keys from the process environment (Phase A), so a developer shell cannot narrow a test. This part builds on part 1 (`.crew/work/2026-11-08-003-knowledge-store-entries-as-markdown-with/plan.md`): `src/engine/module-schemas.ts` and `MODULE_SCHEMAS`, `moduleSchemaState`, the upgrade runner (read as deciding a backup per schema by that schema's own recorded version; step 3 proves it and names the change if it reads otherwise), `knowledge_repos` and `knowledge_entries`, `parseTaxonomy` in `src/modules/knowledge/entry.ts`, `openStore`, `listRepos` (part 1's `resolve.ts`), `ensureFresh`, `plural` in `src/util/text.ts`, `WIZARDINGCODE_MEM_AUTHOR` in `SETTING_KEYS`, and `runCliWith`'s `cwd` (part 1's step 18); it starts when part 1 is on the journey branch.
