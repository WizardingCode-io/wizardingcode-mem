## Findings
- F-1 · Blocker · Task 1, Steps 1, 3 and 4 (plan lines 121-173, 258-301, 329) · The plan no longer matches the noise.ts that was built. Plan line 260 has `SUMMARY = /<summary\b[^>]*>(?:[\s\S]*?<\/summary>|[^\n]*)/g`. The code (src/distill/noise.ts:19) uses `[^\n]*?<\/summary>`, so a summary never crosses a newline. Plan line 299 has the verdict regex `\b(?:[Vv]erdict|[Vv]eredicto)\b[\s\S]*\b(?:REJECTED|…)\b`. The code (noise.ts:53-60) needs the capitalised label, at most 40 characters, a colon and then the verdict word. tests/unit/noise.test.ts:45-47 and :86-87 add cases the plan does not have, so there are 14 tests, not 13. The plan's regex would drop knowledge such as "If the verdict is FAILED, the pipeline halts." Anyone reading or re-implementing Task 1 from the plan gets the old behaviour.
- F-2 · Blocker · Crew (lines 32, 43) and Task 10 Step 6 (line 3280) · `~/.claude/plugins/cache/wizardingcode-plugins/wizardingcode-developer-crew/0.1.4/dist/crew.mjs` does not exist. The only installed engine is `…/0.20.1/dist/crew.mjs`. Every `crew start`, `tdd red/green` and `gate run` command in the plan fails as written.
- F-3 · Blocker · Task 6 Step 1, test "a turn the filter empties…" (lines 1754-1765) and Step 4 "PASS, 14 tests" (line 2318) · The test cannot pass. src/distill/segment.ts:49-52 and :60 treat a one-character token before "." as an abbreviation. So "Quality Gate Verdict: REJECTED — round 2. Status: redo cycle 2/2." is not split at "2." and stays one candidate. Only the `verdict` pattern drops it, so the reason is "noise: verdict", but the test expects "noise: verdict, status-label".
- F-4 · Major · Task 2 `prepareTurn` (lines 758-771), reused by Task 6 `decide` (line 2079) and Task 8 `measure` (line 2904) · `toldInSession` (src/distill/pipeline.ts:144-152) takes every injection of the session with no time limit. `withoutNotes` (src/retrieve/render.ts:108-111) then removes each of those sentences from the turn's text with `replaceAll`. In the live drain only earlier injections exist. In the cleanup, a memory made from this very turn and injected later in the same session is cut out of its own source turn. The turn is then archived as "noise: nothing to judge" or gets a weaker title, and the proof counts a keep as lost. The plan's comment "the notes the session was already shown" is false on this path. Nothing limits injections to `i.at <= turn.ended_at`.
- F-5 · Major · Task 6 `decideAll` and the apply loop (lines 2185-2260), `apply` (2129-2183) · A whole batch of 50 is decided before anything is written, and `apply` never checks the row's current status. If an earlier row's `applySupersessions` supersedes a later pending row in the same batch, the later row is still applied. On the "superseded" path it gets a new active replacement for knowledge that was already superseded; `supersede()` is a no-op on it because of its `AND status = 'active'` guard (src/store/memories.ts:121). On the "kept" path its judge_version is set to 2. Consolidation of later rows also cannot see replacements decided earlier in the batch, so duplicates between replacements are not detected.
- F-6 · Major · Task 6 lease (lines 1939, 2223-2234) · The lease renewal `claimDrain(...)` inside the loop ignores its return value, and it runs only once per batch of 50. Each attempt can take up to 3000 ms and fail twice more after retry delays of 250 and 1000 ms (src/judge/typesafe.ts:51-52), with up to two requests per row (distill and consolidate) and concurrency 4. One batch can therefore outlast `DRAIN_LEASE_MS = 120_000`. A live drain then takes the expired lease (src/store/meta.ts:64-65, :80-85) and both processes write memories. That is exactly what the comment at line 2222 says must not happen.
- F-7 · Major · Task 6 `decide`, consolidation step (lines 2102-2107) · `options.judge` is makeJudge's fallback wrapper (src/judge/index.ts:49-56). When TypeSafe fails, it quietly returns the heuristic's `consolidate` verdict (src/judge/fallback.ts:51-55). The engine checks `verdict.source` only for distill, so supersede and duplicate decisions can come from the heuristic. The heuristic's `contradicts` 0.8 rule (heuristic.ts:209) can then supersede other memories. This contradicts the engine's own header (line 1932), which says a fallback verdict is never written.
- F-8 · Major · Review Focus 4 (line 50) against `decide` (lines 2059-2061) · Focus 4 says a turn whose `final_text` is empty is judged on its own text by `worth` alone. The code falls back to that only when the prompt and final_text are both empty (`hasText` uses `||`). A turn with a prompt and no answer goes through `prepareTurn` and may be rewritten. Task 6 also has no test for an empty final_text; only the orphan case (null turn) is tested.
- F-9 · Major · Task 4 Steps 3 and 7 (lines 1316, 1357-1360) · The grep in Step 3 finds three files that Step 7 does not handle. tests/integration/judge-select.test.ts:27 answers `durable_0`; under version 2 its test at :84-85 (expects `source` "typesafe") fails, because a MissingAnswer falls back to the heuristic. tests/integration/rejudge.test.ts:50-51 has a stub at version "1". Neither file is in Step 7's `git add` list, so the commit either leaves the tree red or leaves the fix uncommitted. The pattern `version: "1"` also matches tests/integration/mcp-global.test.ts:125 (an MCP `clientInfo`), which must not change.
- F-10 · Major · Task 4 Step 5 (golden turns) and Step 6 (lines 1323-1352) · tests/golden/judges.test.ts:56-60, tests/golden/filter.test.ts:13-17 and scripts/record-typesafe.ts:22-27 all build input with `distillInput` (tests/helpers/judge-input.ts:16), which runs neither `stripHost` nor `dropNoise`. The new hand-back, template-leak and gate-verdict turns are therefore recorded and scored on text that production never sends to the judge. The AC-4 floors do not measure the version 2 pipeline, and the plan does not say whether the golden set should go through `prepareTurn`.
- F-11 · Major · Task 5 Step 1, CHECK assertion (lines 1396-1400) · The insert uses `memory_id` 1 in a database with no memories. With `foreign_keys = ON` (src/store/db.ts:170) and `memory_reviews.memory_id REFERENCES memories(id)`, it throws on the foreign key whatever the outcome value is. The test still passes if the `CHECK (outcome IN …)` is left out of the migration.
- F-12 · Major · Task 8 `holds` and `titleIsKnowledge` (lines 2851-2856, 2928-2929) · Titles are clipped to `TITLE_MAX_CHARS = 120` with "…" (src/distill/policy.ts:11; buildDraft at plan line 728). A knowledge sentence longer than 120 characters is then never a substring of its quote, nor the quote of it. "Stored whose title is knowledge", the metric checked against the 60% target, is under-counted, and Task 10's calibration loop reacts to that. An empty quote also matches every title (`a.includes("")`).
- F-13 · Major · Task 8 `measure` (lines 2876-2919) and `rehearse` · `makeJudge` returns the fallback wrapper, so when TypeSafe fails, `draftTurn` quietly returns the heuristic's draft. `measure` never checks `verdict.source`, so the ADR can publish heuristic numbers as TypeSafe's.
- F-14 · Major · Task 9 Step 2, README text (line 3149) · "`--undo` puts everything back" is not what the engine does. `undoRejudgeDistilled` (lines 2279-2287) reverses only the latest `run_id`, and each CLI invocation has its own run id, `${process.pid}-${crypto.randomUUID()}` (line 2553). A cleanup resumed over several invocations, which the design invites, is undone one invocation at a time. The CLAUDE.md text ("reverses the last run") is correct; the README is not.
- F-15 · Nit · Task 7 Step 2, expected failure (line 2465) · The old command would not print "rejudge: 0 judged". The `beforeEach` in tests/integration/rejudge-cli.test.ts:21-31 imports three claude-mem memories, so it judges 3.
- F-16 · Nit · Task 7 `serveV2` (lines 2352-2361) · It loops over `body.state.candidates` without a guard. - F-17 · Nit · Task 6 options "Judge and report, write nothing" (line 1967) and Task 7 dry-run test (line 2401) · A dry run does write: the drain lease in meta, TypeSafe usage counters (src/judge/index.ts:44-47), breaker state, and the report file. - F-20 · Nit · Task 10 Step 4, "the dry run and the run agree on their counts" (line 3265) · A real run writes replacements batch by batch, and later consolidations see them; a dry run writes none. Supersede and duplicate counts can therefore differ for good reason.
- F-21 · Nit · Task 7 `--undo` (lines 2533-2539) · Undo runs even when `--dry-run` is also given, and it takes no drain lease.
