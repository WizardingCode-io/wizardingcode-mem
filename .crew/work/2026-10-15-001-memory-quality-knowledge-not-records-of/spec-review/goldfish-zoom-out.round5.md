## Findings
- F-1 · Nit · Plan Task 5 (`DistillInput.wording`, `IMPORT_JUDGE_VERSION`) and spec §2 "Versions" · The version is stated in two places that nothing ties together. The request's wording is chosen by a new `wording?: 1 | 2` field on the shared `DistillInput`, which the heuristic judge ignores. The stamp is a separate hard-coded `"1"` in rejudge.ts. Meanwhile `TypeSafeJudge.version` says "2" even when it asks the version 1 questions, so the judge's own version no longer describes what it asked. Only the AC-10 test keeps the two in step. A simpler shape would derive the stamp from the wording that was sent, for example one constant used both to build the input and to stamp the row.
- F-2 · Nit · Plan Task 7, `measure` (the hand-built `QueuedTurn`) · The proof fills in 14 `QueuedTurn` fields, with placeholders such as `agent: ""`, `cwd: ""` and `transcriptPath: null`, only to call `prepareTurn`. `prepareTurn` reads four of them: `sessionId`, `endedAt`, `prompt` and `finalText`. Narrowing `prepareTurn`'s parameter to those four fields would make the shared seam honest about what it needs. As written, the proof depends on the shape of the drain's queue type and has to change whenever that type changes.
- F-3 · Nit · Spec §6 "Metrics", the sentence "Both columns are measured by the proof" · That sentence is false for two rows. The version 1 input-token figure is quoted from ADR 0005, not measured. The version 1 "lost" figure is 0 by definition. The plan's report and ADR frame label these honestly; the spec's sentence should do the same.
- F-4 · Nit · Spec §7 "Risks and limits", first row ("The `keep lost` metric") · No metric has that name. §6 calls it "`knowledge` or `mixed` turns lost". Use one name for it.
- F-5 · Nit · Plan Task 8, Step 2 (ADR 0023 frame: "Status: accepted; measured on two labelled samples") · The ADR is committed in Task 8 saying it was accepted and measured, before Task 9 has measured anything. Spec §6 says a missed target on sample B blocks the merge. If that happens, the branch holds an ADR that states something false. The frame should be committed as proposed, and its status set from the result in Task 9.
- F-6 · Nit · Plan Task 6, Step 6 (the replaying judge in tests/golden/judges.test.ts) · Every `distill` call runs `distillInput` over all 40 golden turns and compares texts to find which turn is being judged. That is O(n²), and two turns that are identical after filtering cannot be told apart. The harness already knows which turn it is replaying, so passing the id, or building one map from filtered input to id before the loop, is simpler.
