## Findings
- F-1 · Major · Task 7, "Title is knowledge" bullet (line 1451) and `titleIsKnowledge` in quality.ts · The spec (§6, metric table) says a title counts as knowledge when "the title's full sentence is a `knowledge` memory's sentence or a `mixed` one's quoted sentence". The plan's code requires a match against a quote for both labels. An engineer building it as written would undercount both the version 1 and version 2 columns for `knowledge` memories: a version 2 title that is a different knowledge sentence from the one quoted fails the match. Those wrong numbers would go into ADR 0023 and into the merge decision on sample B. The plan also says the spec wins where the two differ, so the engineer has a conflict with no ruling. The plan needs to state which definition the code implements and, if it narrows the spec, say so.
- F-2 · Major · Task 9, Step 3 (calibration) · The three remedies only cover a quoted sentence the filter dropped, a quoted sentence inside a stripped host block, and a lost turn rated under the threshold. Nothing says what to change when "title is knowledge" is under 60% or "stored from record or fragment" is over 15% with no lost turn and no filter cause. Even for a lost turn, the engineer must choose between `KNOWLEDGE_THRESHOLD`, `SAVE_THRESHOLD` and a criterion's wording, with no order and no direction. Two engineers would tune different levers on sample A, and B's numbers in the ADR would depend on which one they picked. The plan needs a lever order per missed target, a direction, and the step size for each.
- F-3 · Major · Task 9, Step 6 · The ruling file is given only as key names: `{"rulings":[{"gate","verdict","reviewer","judge","findings","tokens"}]}`. It gives no types, no allowed `verdict` values, no shape for `findings` and no unit for `tokens`. An engineer would guess, for example `"pass"` against `"PASS"` against `"approved"`, or findings as a string against an array. `crew judgement record` would then reject the file or record something the engineer did not mean. The plan needs one complete example ruling, or a pointer to the engine's schema.
- F-4 · Nit · Task 6, Step 7 · "Adjust the wording of the criterion that misled it" hands the engineer a design choice: which criterion, and what new text. The stop-after-a-second-recording rule limits the risk, so this is only a note.
- F-5 · Nit · Crew table and Task 3 header · AC-1 is listed against Task 3 ("1 (done), 3"), but Task 3 records only AC-3, AC-2 and AC-11 with `crew tdd`. Say whether AC-1 needs another red/green record in Task 3, or remove 3 from its Task column.
- F-6 · Nit · Task 6, Step 4 table against Step 6 · The replaying judge's lines are given as "34–35, 37" in the table and "34–37" in Step 6. The replacement block actually covers lines 34 to 39, the closing `},` of `distill`. Give one range for the replacement.
- F-7 · Nit · Spec §5, critical journeys · The journey "A live turn that is only a status line" ("Status: done. Next I open the PR." with a two-word prompt, no memory stored) has no named test in Task 3. The other four journeys are covered.
