## Findings
- F-1 · Major · File Structure (lines 65–90) and the per-task **Files** lists in Tasks 3, 4, 5 and 6 · The File Structure table has no Create/Modify/Delete column. Tasks 3–6 label test files `Test:` instead of `Create` or `Modify`: `Test: tests/unit/draft.test.ts (new)` at line 222, `Test: tests/unit/heuristic-judge.test.ts (one describe added)` at 727, `Test: tests/integration/rejudge.test.ts` at 903, `Test: tests/unit/questions.test.ts (new)` at 1063. Task 7 writes "modify" in lower case inside a `Create:` line (1437). An implementer can't tell from the label whether to create a file or edit one. `tests/unit/draft.test.ts` shows the risk: it is marked "(new)" but already exists in the working tree as an untracked file, and only the prose at line 217 says to overwrite it.
- F-2 · Major · Task 7, `measure` label validation (lines 1806–1813) and `quotesOf`/`lost`/`titleIsKnowledge` (1737–1751); "Labels" bullet at line 1454 · `measure` refuses only an unknown label name. A `knowledge` or `mixed` label with no quote, or only empty quotes, is accepted. `quotesOf` then returns `[]`, so `lost()` is true and `titleIsKnowledge()` is false for that turn, whatever the pipeline produced. The brief says "Never leave a quote empty" (line 1503), but nothing enforces it. One careless label adds a "lost" turn against a target of 0, which blocks the merge (Task 9 Step 3, spec section 6). The plan should make `measure` refuse such a label, as it refuses unknown names.
- F-3 · Major · Task 7, "Title is knowledge" (line 1451) and `titleIsKnowledge` (1738–1741), against spec section 6 line 224 · The spec counts a title as knowledge when "the title's full sentence is a `knowledge` memory's sentence or a `mixed` one's quoted sentence". The plan matches only the quotes for both labels. A `knowledge` memory whose new title is a different, unquoted sentence of that memory is counted as not knowledge, which pushes the metric down against its ≥ 60% target. Line 11 makes the spec the source of truth, so as written the implementer builds a different metric from the one the spec defines.
- F-4 · Major · Task 3 Step 5(d) `toldInSession` bound (lines 583–597) and Review Focus 3 (line 61) · `injections.at <= turns.ended_at` assumes `ended_at` is when the turn ended. The code moves it later in three places:
  - `completeTurn` re-ends a `done`/`skipped` turn with `ended_at = turn.now` (src/store/turns.ts:139–145; its comment at 123–124 says a turn-end can arrive after the next prompt).
  - `interruptOpenTurns` sets `ended_at` to the time of the next prompt (turns.ts:80).
  - `abandonStaleTurns` sets it to the time of the sweep (turns.ts:156).

  In the re-ended case, the memory made from the first ending may have been shown before the late turn-end. It then passes the bound and removes the turn's own sentences when the turn is distilled again, which is the failure Review Focus 3 exists to prevent. The plan neither handles nor names this case, and no test covers it.
- F-5 · Major · Task 7 Step 5 smoke runs (lines 2031–2035), with the guard in `quality.ts` (1575–1602) · The smoke runs call `quality.ts` directly with only `WIZARDINGCODE_HOME` set. They do not clear `WIZARDINGCODE_MEM_DATA_DIR` or `WIZARDINGCODE_MEM_STORE_DIR`, which the shell wrapper does. `quality.ts` builds its "live" directories by deleting exactly those two variables, then opens `resolvePaths().storeDir`, which does honour them (src/util/paths.ts:13–14, 34–35). If the author's shell exports either variable for the live store, and the env file does not also name it, the guard misses it. `openDb` then opens and migrates the live database (src/store/db.ts:162–172). That breaks the global constraint at line 24. The smoke commands should unset these variables, or the guard should treat them as live when `LIVE_DATA`/`LIVE_STORE` are absent.
- F-6 · Nit · Task 7 `measure` loop (line 1819, `if (row === undefined) continue;`) · A label whose id is not an eligible row is dropped without a message. "Labelled: N" in the report then shrinks without saying why. One stderr line or a count in the report would make it visible.
- F-7 · Nit · Task 3, the live drain (Step 5(e), lines 665–673) · `distillTurn` discards `prepared.dropped`. A turn the filter emptied and a turn the judge rejected both end as `state = 'skipped'` with `last_error = NULL` (src/distill/pipeline.ts:176–180). Outside the proof there is no log, count or column showing which sentences the filter dropped, or which turns it emptied. Someone debugging a missing memory later can't tell which of the two skips happened.
- F-8 · Nit · Criteria table line 40 and Task 3 heading line 215 · AC-1 is mapped to Task 3 ("1 (done), 3"; "Criteria: AC-2 and AC-1"), but Task 3 records only AC-2, AC-3 and AC-11 (`crew tdd red/green` at lines 460–462 and 680–682). Either add the AC-1 runs or drop Task 3 from AC-1's row.
