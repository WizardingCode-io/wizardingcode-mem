## Findings
- F-1 · Major · Task 6, `PENDING_WHERE` (and Task 8 `ELIGIBLE`) · When the author edits a memory in the viewer, `src/ui/api.ts:344` sets `judge = 'user', judge_version = '1'` and leaves `origin = 'distilled'`. The filter `origin='distilled' AND status='active' AND judge_version='1'` therefore picks up the author's hand edits. Their edited title will not match the new draft, so the cleanup supersedes them, or archives them, or on "kept" overwrites `judge` with 'typesafe'. Only `user_memories` rows are excluded. The plan needs to say whether `judge = 'user'` rows are excluded, and needs a test for it.
- F-2 · Major · Review Focus 4 vs Task 6 `decide` · Review Focus 4 says "a turn whose `final_text` is empty is judged on its own text". The code falls back to the memory's own text only when both `prompt` and `final_text` are empty (`hasText = prompt !== "" || finalText !== ""`). A turn with a prompt and an empty answer is re-distilled from the prompt, and it can then be superseded. No Task 6 test covers an empty `final_text`. The engineer cannot tell which rule is the intended one.
- F-3 · Major · Task 6 `rejudgeDistilled` / `decideAll` · The engine makes every decision in a batch of 50, then writes them all. `consolidate` for row k never sees the replacements written for rows 1..k-1 of the same batch. Two turns that teach the same fact therefore produce two active replacements, where the live drain, which runs one turn at a time, would reinforce one. This holds even with `--concurrency 1`. The risk is not stated and no test covers it. Either write each decision before the next is made, or accept the duplicates explicitly.
- F-4 · Major · Task 6, drain lease · `claimDrain` is renewed only once per batch, with `DRAIN_LEASE_MS = 120_000`. A batch of 50 at `--concurrency 1`, each turn making a distill request plus a consolidate request (with a 3 s timeout and retries), can run past 120 s. The live drain then takes the expired lease and writes at the same time, which the plan's own comment says must not happen. Renew the lease per decision, or bound batch time against the lease.
- F-5 · Major · Task 3 (Steps 4–5) · Changing `heuristicJudge.versions` to `{ heuristic: "2" }` breaks `tests/unit/typesafe-judge.test.ts:412` (`expect(judge.versions).toEqual({ typesafe: "1", heuristic: "1" })`, because `withFallback` merges the two). Task 3 runs only the unit and golden heuristic tests and commits without `bun run test`, so the commit is red. The report penalties can also drop memories in integration fixtures (backfill, history, e2e) that contain "merged", "pushed" or "closed", and nothing in Task 3 catches that. Name the file and the new expected value (`{typesafe:"1", heuristic:"2"}`, not "2+2"), and run the whole suite before the commit.
- F-6 · Major · Task 4 Step 3, the grep instruction · `grep … 'version: "1"'` also matches `judgeVersion: "1"` in about 40 fixture files, and `clientInfo: { version: "1" }`. That includes `tests/golden/retrieval.test.ts:45`, which the Global Constraints require to stay byte-identical. "Update every hit" therefore tells the engineer to break a constraint. The grep also hits `tests/integration/judge-select.test.ts:27` (`durable_0`), which must become `knowledge_0` or that test falls back to the heuristic and fails, but the Step 7 `git add` list leaves that file out. List the exact files and lines to change instead of a grep.
- F-7 · Major · Task 4, golden set · `tests/helpers/judge-input.ts` (`distillInput`), used by `tests/golden/judges.test.ts`, `filter.test.ts` and `scripts/record-typesafe.ts`, does not run `stripHost` or `dropNoise`. The new golden turns written to exercise the filter (`en-none-hand-back`, `en-none-template-leak`, `pt-none-gate-verdict`) reach both judges unfiltered, and TypeSafe is recorded on input the live pipeline never sends. The plan does not say whether `distillInput` should call `prepareTurn`-equivalent logic. Without that, the "golden floors hold" claim of AC-4 measures a different pipeline from the one shipped.
