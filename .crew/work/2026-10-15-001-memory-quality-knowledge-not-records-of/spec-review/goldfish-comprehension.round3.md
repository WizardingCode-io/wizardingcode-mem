## Findings

**What this proposes**
The change makes the mem store knowledge (rules, decisions with reasons, causes and fixes, pitfalls, how things work) and stop storing records of a session (statuses, verdicts, merges, plans). It has four parts. First, a noise filter runs before the judge: `stripHost` removes the host's framing blocks, and `dropNoise` drops sentences matching three named patterns. D-3 removes two older patterns, protocol-tag and verdict. Second, version 2 judge questions name a fixed `reader`, ask `knowledge_<i>` for each sentence (replacing `durable_<i>`), and say outright what is not knowledge. Third, a stricter policy: the title must be a sentence rated as knowledge or no memory is stored, and `Context:` needs a prompt of at least 5 words. Fourth, the keyless heuristic judge gets a version 2 with report penalties. The import rejudge stays on version 1. A proof runs on two samples of 200 memories each, labelled by an agent from a read-only copy of the author's store, and gates the merge against targets: title is knowledge ≥ 60%, 0 knowledge lost, ≤ 15% stored from records.

**How the existing system works, per this document**
Each finished turn (the prompt plus the assistant's final answer) is queued. A background drain, holding a lease in `meta`, distils queued turns one at a time. In distilling, `withoutNotes` removes sentences the session was already shown, `candidates()` splits the text into sentences, and one TypeSafe request (or the local heuristic) answers worth, kind, importance, a durability for each candidate, and a title choice. `policy.ts` turns those numbers into a draft, which is then consolidated against neighbouring memories. Memories record `judge_version`. Imported claude-mem memories are rescored by `rejudge`. Today, `worth` plus one durable sentence is enough to store a memory, and the judge's title choice is used whether or not that sentence is durable.

- F-1 · Blocker · Spec §5, first critical journey ("Status: done. Next I open the PR.") · The journey says `dropNoise` drops "Status: done." and the judge then rates "Next I open the PR." below threshold. But `segment.ts` already discards any sentence under 20 characters (`MIN_CHARS = 20`, line 106). "Status: done." is 13 characters and "Next I open the PR." is 19, and a two-word prompt is also too short. So `candidates()` returns nothing, the filter never sees the status line, and the turn is skipped with no request. Anyone who writes this journey as a test (a `status-label` drop plus a judge rating) gets a test that fails. The spec never mentions the segmentation minimums (20 characters, 3 words), and they decide what reaches the filter.
- F-2 · Major · Spec §6 Metrics, "knowledge or mixed turns lost", Version 1 column "0 (the sample is what was stored)"; plan Task 7 report hard-codes this · The brief (plan Task 7 Step 2) lets the labeller quote the knowledge sentence "from the title, the body or the turn's text". A `mixed` memory whose knowledge sentence sits only in the turn was in effect lost by version 1, so version 1's figure is not 0 by definition. The report prints 0 instead of computing it. A reader of the ADR would conclude version 2 lost knowledge version 1 kept, when version 1 lost the same turn. A loss version 2 shares with version 1 would also block the merge, because the target is "0; each loss named".
- F-3 · Major · Spec §6 Metrics, "Title is knowledge ≥ 60%" and "Stored from record or fragment ≤ 15%" · The spec does not give the denominator. The plan uses stored memories (`of s.stored`). The version 1 figure of "62% in the 2026-10-13 sample" is a share of all 200 memories, which only matches because every version 1 sample memory is stored. Someone implementing from the spec alone could divide by labelled turns, which gives different numbers and a different pass/fail. Because the denominator is stored memories, a version 2 that stores very little can meet both targets; the spec should say whether that is intended.
- F-4 · Major · Spec §1 "The notes the session had been shown" · The spec gives the bound `injections.at <= turns.ended_at` but not the case where `ended_at` is NULL (`QueuedTurn.endedAt` is `number | null`). A literal SQL `i.at <= NULL` excludes every note, so `withoutNotes` would stop removing anything for those turns. The plan chooses "with no end recorded, every note counts" (`? IS NULL OR i.at <= ?`), but only in code. The spec, which the plan calls the source of truth, is silent.
- F-5 · Nit · Spec §3, Facts ("the five strongest knowledge sentences, the title among them … the title is not repeated in the body") · The plan's `buildDraft` takes the top 5 and then removes the title. When the title is the judge's choice and not among the top 5, the memory carries 5 facts plus the title. That contradicts "the title among them", and the spec does not say whether the title counts toward `MAX_FACTS`.
- F-6 · Nit · Spec §5, "A mixed turn" · The journey depends on the first sentence being rated below `KNOWLEDGE_THRESHOLD` but never says so. With only "rates the second sentence as knowledge", a reader cannot tell why the judge's title choice is overridden.
- F-7 · Nit · Spec §6 Metrics, intro "Both columns are measured by the proof" · The tokens row's version 1 value is "≈ 1,200–1,450 (ADR 0005)", a cited figure, not a measured one, and the ADR frame shows it that way. The sentence and the table disagree.
- F-8 · Nit · Spec §7 Risks, "The `keep lost` metric" · No metric has that name; the metrics table calls it "knowledge or mixed turns lost".
- F-9 · Nit · Spec terms, undefined or only implied: `compact` (§7), "consolidated against neighbouring memories" and the `personal` question (Pipeline order, §2 Versions), "`rejudge` with no subcommand" (which subcommands exist?), "the moved store" (§6, explained only in the plan's shell script), `skipped` as a turn state and the other states, `prepareTurn`/`draftTurn` (§6, defined only in the plan), and claude-mem. A newcomer can guess most of these from context, but not `compact` or the rejudge subcommands.
- F-10 · Nit · Spec D-3, "0.88 whole-memory precision" · "Whole-memory precision" is not defined. The rationale also reads backwards to a newcomer: patterns with 0.80–0.88 precision are removed as "not measured", while `status-label` (4 hits) and `template-label` (2 hits) stay as "measured". One sentence saying the criterion is "no knowledge hit", not sample size, would settle it. §1 says roughly this, but D-3 does not.
- F-11 · Nit · Spec Goals ("No knowledge the version 1 pipeline kept is lost") vs §6 "If a target is missed … accept a named loss" · The goal is stated as absolute and the escape clause relaxes it. Say which one governs.
- F-12 · Nit · Spec §4, "a verdict word (the lists are in the code)" · The plan's `VERDICT` regex is case-sensitive (`verdict|veredicto|REJECTED|APPROVED`), so "Veredicto da ronda 3" or "Quality Gate Verdict:" is caught only through another word. Neither document says whether that is intended.
- F-13 · Nit · Plan, Crew section · "full route", "build phase", "judgement gates" and AC-8 (which AC-11 "supersedes") are used without definition. Task 3 tells the executor to "record the red runs again" without saying whether crew accepts a second red record for the same criterion.
- F-14 · Nit · Plan Task 9 Step 3 · After three calibration changes on A, the plan does not say what to do if A still misses a target: run B anyway, or stop and hand the report to the author. The spec's "the author decides" is written only for B.
