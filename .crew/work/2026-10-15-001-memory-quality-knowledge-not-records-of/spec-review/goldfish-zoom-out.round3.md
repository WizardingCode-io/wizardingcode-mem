## Findings
- F-1 · Major · Spec §5 step 1 ("Build the turn's input exactly as the live path does (`withoutNotes`, …)"); plan Task 2 `prepareTurn` / Task 6 `decide` · Running the live preparation on an old turn is not the same as running it live. `toldInSession` reads every injection of the session with no time bound, and `withoutNotes` deletes any told sentence of 20 or more characters from the turn's text. When the cleanup runs, that set includes notes injected after the turn, among them the v1 memory made from this very turn if a later prompt in the same session recalled it. Its title and facts are the turn's own sentences, so they are removed before segmentation. The memory is then archived as "nothing to judge" or "no knowledge", and the memories most likely to be hit are the ones useful enough to have been recalled. The proof's `measure` uses the same path, so the bias also reaches the numbers in the ADR. Because `injections.at` exists, the told set can be limited to injections made before the turn ended (or this turn's own memories can be excluded). The spec should state that rule, and a test with a self-injected memory should pin it.
- F-2 · Major · Spec §5 "Reversibility" ("`--undo` reverses the last run") together with "bounded by `--limit` and resumable"; plan Task 6 `undoRejudgeDistilled`, Task 7 `owner: ${pid}-${uuid}` · Each CLI invocation is a new `run_id`. A cleanup that is done in pieces (`--limit`, or a run stopped by five failures and resumed, both of which the design invites) can only be undone one piece at a time, newest first, and the command never says which piece it undid or how many are left. The rehearsal in §6 runs once, uninterrupted, so it cannot catch this. A competent builder delivers the plan as written and believes "reversible" covers the whole cleanup. Either define a run as all reviews since the last undo (or the last complete pass), or have `--undo` report the run it reversed and the number still recorded. A test should resume, undo and compare counts.
- F-3 · Major · Spec §5 step 3 ("dated as the old one … so recency does not change") and "Nothing else moves … Retrieval … unchanged" · The replacement is a new row. It starts with `use_count` 0, which `src/retrieve/notes.ts` uses in ranking (`1 + log1p(useCount)`), with `evidence_count` 1 and no `memory_sources` evidence, and with `updated_at` equal to the old `created_at`. Retrieval code is unchanged, but what it ranks is not: every superseded memory loses the usage and reinforcement it had built up. This happens in volume. The spec counts 912 memories with a short-acknowledgement `Context:` line, and the v2 draft drops that line (CONTEXT_MIN_WORDS), so the `kept` identity check fails and those memories are superseded even when the title is unchanged. The spec takes care over `created_at` and misses the other ranking inputs. It should either carry `use_count`, `evidence_count` and `updated_at` over to the replacement, or state the ranking change and measure it.
- F-4 · Nit · Plan Task 6 `decide` (builds `QueuedTurn` by hand) and Task 8 `measure` (builds it again) · A third copy of the turn-row-to-`QueuedTurn` mapping. `claimNextTurn` in `src/distill/queue.ts` already selects exactly these columns. A small `turnById(db, id): QueuedTurn` beside it in `src/store/turns.ts` would serve the drain, the cleanup and the proof. In the same vein, `measure` re-implements a per-turn dry run that `rejudgeDistilled({ dryRun, onLine })` already performs, so the proof measures a sibling path rather than the one the author will run (no consolidation, no `kept` branch).
- F-5 · Nit · Spec §1 "`stripHost(text)` … Removed from the final message"; plan Task 2 `prepareTurn` applies it to the prompt too · Applying it to the prompt is harmless and probably right, since `isFromTheHost` only catches a prompt that opens with a host tag. But the spec and the plan disagree, and the spec should say that both texts are stripped.
- F-6 · Nit · Spec §5 "Only one run at a time (the drain lease is taken for the run…)"; plan `rejudgeDistilled` claims the lease in dry-run mode too · A dry run writes nothing but holds the drain lease for the whole pass (around 2,500 requests plus consolidations), so live distillation waits for the length of a read-only rehearsal. A dry run needs no lease, and the spec should say so.
