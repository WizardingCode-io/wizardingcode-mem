## Findings
- F-1 · Major · Spec §5 "Reversibility" / Plan Task 6 `apply` (the `kept` branch) and `undoRejudgeDistilled` · The spec says the cleanup is "Reversible" and that `--undo` "reverses the last run". In the plan, a `kept` outcome overwrites `kind`, `importance`, `judge` and `judge_version` in place and stores none of the old values, and undo then leaves kept memories as they are. The same holds for orphan memories kept by `decideOnText`. The rehearsal (spec §6, plan Task 8 `rehearse`) compares only status counts, so it cannot catch this. A reader would trust undo to put the base back when part of the run cannot be undone. Either record the old kind and importance in `memory_reviews`, leave kept memories untouched apart from the version, or say plainly that kept memories are re-labelled without undo.
- F-2 · Major · Plan Task 6 (`src/judge/rejudge-distilled.ts`) and Task 7 (`runDistilled`) · Most of this is a second copy of `src/judge/rejudge.ts` and of `run()` in `src/cli/commands/rejudge.ts`. `decideAll` repeats `judgeAll`'s worker pool line for line. `STOP_AFTER_FAILURES` is declared again. The loop of `pending`/`remaining`/`afterId` cursor/limit, the "TypeSafe or failed" check, `decideOnText`'s input (a copy of `asInput`, but without the `filesChanged` that `asInput` sends), the key-refusal message, the TTY progress line and the token/cost accounting all exist already. The spec presents it as "as `rejudge` does", but the plan copies the code rather than sharing it. As a result, the next change to failure or stop semantics, or to the judge input for a memory with no turn, will reach one path and miss the other. The worker pool, the failure breaker and the CLI frame (key check, progress, cost line) should be extracted once and used by both commands.
- F-3 · Major · Spec §2 "Versions" vs §5 "Not in this change" and "Out of scope" · §2 says plain `rejudge` (imports) will now ask the version 2 `worth`/`kind`/`importance` wording. §5 and Out of scope say the imported memories, and "`rejudge --imported` with the version 2 questions", are a separate decision. Both cannot be true. Once this lands, any run of `rejudge` judges the 67,301 imported memories with unmeasured version 2 criteria, archives by them and stamps `judge_version = '2'`. The plan's README line still describes it as judging imports "properly". A reader would miss that the population declared out of scope changes behaviour. Pin the import rejudge to the version 1 wording, or bring it into scope and measure it.
- F-4 · Nit · Spec §5 "Reversibility: `memory_reviews`" and the plan's migration comment · The table is justified as making the run "resumable without a cursor", but that already follows from the data. Superseded and archived memories leave `status = 'active'`, and kept ones become `judge_version = '2'`, so `pending()` already skips them, just as `rejudge` resumes on `judge = 'claude-mem'` with no table. Only undo needs the table. `history_replacements` with `restoreImports` (`src/backfill/replace.ts`) is the existing precedent for an undo list of archived memories, and the spec does not mention it. Say that the table exists for undo, and follow or extend that precedent.
- F-5 · Nit · Spec §5 step 3 vs Plan Task 6 `nextOrdinal` and Task 9 CLAUDE.md text · The spec and the CLAUDE.md line say the replacement gets `source_ordinal = 1`. The plan uses `MAX(source_ordinal) + 1`, which gives 2 on a re-run after `--undo` (the archived replacement still holds 1). The documented value is wrong in that case.
- F-6 · Nit · Spec §5 table (`outcome 'kept'`) · Steps 1–4 of "What it does, per memory" never define a `kept` outcome. The plan invents it ("the reading is identical", which also re-labels the memory; see F-1). Define it in the spec.
- F-7 · Nit · Spec §5 step 3, §1 and §4 (altitude) · The design section carries implementation detail: `NewMemory` gains `sourceOrdinal` with default 0, `findNeighbours` already excludes the memory's own turn, the full Portuguese/English status-verb lists, `−0.25` per sentence with floor 0.05. The rule and its intent belong in the spec; the lists, constants and helper names belong in the plan or the code.
- F-8 · Nit · Spec §1 intro · It names "the archived knowledge module's `episodic.ts`" as the model for the shape. No such file exists in the repository; it survives only in ADR 0020. Point at the ADR, or drop the reference.
- F-9 · Nit · Plan Task 8 `shuffled` · A seeded shuffle is written anew, although `scripts/proof/moments.ts` already has `generator`/`sample` for deterministic seeded sampling in the proof scripts. Reuse it, or move one shared helper next to `live-guard.ts`.
- F-10 · Nit · Spec §4 and Plan Task 3 · The heuristic version 2 penalties are labelled "starting values", but the proof in §6 needs TypeSafe and never measures the heuristic. Their only check is the golden set, whose eight new turns were written from the same sample shapes the penalties target. Keyless installations get report penalties that no measurement backs. Either state this limit in the ADR, or score the heuristic on sample A as well.
- F-11 · Nit · Plan "Crew" section and Task 10 Step 6 · The crew engine path `.../wizardingcode-developer-crew/0.1.4/dist/crew.mjs` does not exist; the installed engine is under `0.20.1`. As written, the command fails.
