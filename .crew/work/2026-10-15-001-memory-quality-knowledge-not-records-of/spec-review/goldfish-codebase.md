## Findings
- F-1 · Major · Task 3 Step 5(c) `prepareTexts`/`buildDraft` (plan lines 723, 778–794, 818–828) and the test name "host blocks and noise sentences never reach the judge" (line 432) · The plan says filtered text never reaches the judge, but its code does not do that. The judge's `user_prompt`/`assistant_final_message` and the `Context:` line come from the output of `stripHost`, not from the kept candidates. `stripHost` removes only the tagged block (src/distill/noise.ts:17–28). `isFromTheHost` matches only a prompt that *starts* with `<task-notification`/`<agent-message` (src/core/host-prompt.ts:5). So for a prompt shaped like the plan's own golden turn `en-none-hand-back` (line 1584), the frame lines "Another Claude session sent a message:" and `That "other Claude session" is an agent…` survive. They have at least 5 words, so a memory titled from the answer gets `Context: Another Claude session sent a message: …`. That is the same host-framing leak spec line 33 counts (38 memories). The same gap applies to the judge: in NOISY_ANSWER, `Status: looked into it.` and `agentId: …` still reach the judge in `assistant_final_message`, which contradicts AC-1's "never reach the judge". The test at line 446 checks only the candidates and `<summary`. A builder would ship the leak and believe it closed.
- F-2 · Major · Task 7 guards (plan lines 24, 1799–1813, 2307–2308) · `WIZARDINGCODE_HOME` is ignored. `defaultDataDir` honours it (src/util/paths.ts:13–21). `quality.sh` defaults `LIVE_DATA` to `$HOME/.wizardingcode/mem`, and `quality.ts` explicitly drops `WIZARDINGCODE_HOME` when it works out `live`. If the author has moved the brand home, the proof copies the wrong store (or none), and neither guard treats `$WIZARDINGCODE_HOME/mem` as live data. The Global Constraints list of live locations omits it too.
- F-3 · Major · Task 7 "What runs per turn" and `measure` (lines 1667, 1866–1869, 2081–2095) · The plan says `measure` runs "the drain's steps up to the draft", but it leaves out the drain's first skip: `detail.savedMemory` (src/distill/pipeline.ts:181–185). `storedDetail` always returns `savedMemory: false` (pipeline.ts:78). Sample S (`t.state = 'skipped'`) therefore includes turns the drain skipped because the agent saved a memory itself, and v2 will "store" them. That inflates "memories stored" and the denominator of "stored from record or fragment, of B and S". Nothing in `turns` records why a turn was skipped (spec line 293). The plan must decide how S excludes these turns, or say that they count.
- F-4 · Major · Task 7 `measure`, the `TypeSafeJudge` it builds (lines 2055–2061) · The proof uses `timeoutMs: 10_000`. The live drain uses the default of 3000 ms: src/judge/typesafe.ts:51, and `makeJudge` sets no timeout (src/judge/index.ts:40–48). A v2 request, up to 2× larger under D-5, that would time out live and fall back to the heuristic counts in the proof as a TypeSafe verdict. Neither the "failed" count nor any metric reflects live behaviour, and the plan does not state or measure the difference.
- F-5 · Major · Task 7 `norm`/`fullSentence`/`factsOf` (lines 1916–1929) and the brief's "verbatim, as written in the turn" (line 1722) · Titles and facts are segmenter output. The segmenter strips single-asterisk emphasis, `> ` quote marks and a `[ ]`/`[x]` checkbox after a bullet, and clips sentences over 400 characters with "…" (src/distill/segment.ts:8, 16–17, 69–73, 97–99, 111). `norm` undoes only `**`, a leading list marker, whitespace and case. A verbatim quote of such a sentence can never match. That counts the turn as "lost" and lowers "title is knowledge" for every version, and both metrics gate the merge (≥60%, lose none).
- F-6 · Nit · Task 3 Step 3, expected red for the status-report journey (line 618) · "the old policy stores the judge's title" is false. `judging({}, null)` gives `titleIdx` null and 0.1 everywhere, and today's `buildDraft` finds no durable sentence, so it returns null (pipeline.ts:110–112). Today's code stores nothing, and the test fails only on the candidates assertion.
- F-7 · Nit · Task 3 Step 7 (line 858) · "no fixture carries host blocks" is inaccurate. tests/integration/distill.test.ts:504–524 has `<task-notification>` and `<agent-message>` prompts; `isFromTheHost` already handles them.
- F-8 · Nit · Global Constraints (line 22) · "the new code is only reached from `distill`, `rejudge` and the proof" leaves out `history import`, which drains through `drainQueue` (src/backfill/run.ts:8).
- F-9 · Nit · Task 6 Step 6, golden turn `en-none-hand-back` (line 1584) · Spec §9 (spec line 216) asks for "a subagent's hand-back quoted in the answer". The plan puts it in the prompt, so the golden set never exercises the answer-side hand-back that AC-2 empties. The plan's line 11 says the spec wins, and this difference is not listed.
- F-10 · Nit · Task 7 samples and labels (lines 1665, 1891–1896, 2005–2031) · One `generator(seed + 1)` is shared across a, b and s, so check-b depends on how many draws check-a consumed. The text says each sample's check "comes from `generator(seed + 1)`". `readLabels` also reports neither duplicate labels for one turn nor sample turns left unlabelled.
- F-11 · Nit · Task 7 `quality.sh` (lines 2307–2324) · `LIVE_STORE` taken from `WIZARDINGCODE_MEM_STORE_DIR` is not required to be absolute, unlike `storeDirOf` (src/util/paths.ts:35–37). Also, when `$LIVE_DATA` does not exist, `$(cd "$LIVE_DATA" && pwd -P)` expands to empty, the case pattern becomes `/`*, and every work dir is refused with a misleading message.
- F-12 · Nit · Task 7 Step 5 smoke runs (lines 2374–2377) · `TYPESAFE_API_KEY=apikey_invalid` makes real requests to api.typesafe.ai carrying the smoke text. The plan does not say the smoke run goes on the network, which the Global Constraint on line 25 implies needs saying.
