# risk findings for 2026-10-15-001-memory-quality-knowledge-not-records-of

## Findings
- F-1 · advisory · src/distill/pipeline.ts:318 · In the live drain, nothing records which sentences the noise filter dropped or what `stripHost` cut: `prepareTurn` returns a `dropped` list and `distillTurn` throws it away. A filter-emptied skip and a judge rejection both end as `skipped` with `last_error = NULL` (lines 319-321). So if a pattern or a cut-short block tag (src/distill/noise.ts:53, which removes everything from the tag to the end of the answer) starts eating knowledge in daily use, nobody would see it in the first hour or the first week. Only the offline proof reports drops. The spec names this risk (design §12, line 299), and the turn text stays in `turns` for 90 days, so this is advisory rather than invisible-and-irreversible.
- F-2 · advisory · docs/superpowers/specs/2026-10-14-memory-quality-design.md:292 · The only way to undo version 2's lost turns (10% of knowledge and mixed turns on B, 11 of them kept by v1; ADR 0023 lines 98 and 108) is to re-distill them later. That depends on the separate cleanup item D-1, which is not built yet, and on doing it within `compact`'s 90-day window. After 90 days those skips can no longer be recovered. The spec states this dependency, so it stays advisory, but no owner or date is named for D-1 before the window closes.
- F-3 · advisory · src/distill/policy.ts:14 · The first `history import` run after the upgrade (up to `historyDays`=180 days of transcripts) will judge every turn with the version 2 questions: about 1.29x the input tokens per turn and about 6,000 tokens per real turn (ADR 0023 lines 102-106). It will also store fewer memories. The run is bounded by `--max-seconds` and resumable. The ADR measures the cost per turn but never estimates the cost of that run.
- F-4 · advisory · src/backfill/replace.ts:68 · `history replace-imports` archives the claude-mem imports inside a finished project's history span. Version 2 now distils fewer memories from that history, so a replace run after this change leaves the archived imports with fewer replacements than before. `history restore-imports` undoes this, by hand. Neither the spec nor the ADR mentions how version 2 interacts with replace-imports.
- F-5 · advisory · .crew/work/2026-10-15-001-memory-quality-knowledge-not-records-of/plan.md:13 · The rollback is "a release" (spec.md:33, design §13 line 305), but the plan never names the release steps: version bump, `bun run plugins`, and the per-agent plugin update. Different agents may run v1 and v2 binaries against the same store for a while. That mix is harmless, because each row is tagged with its `judge_version`, and older binaries read v2 rows without trouble: `judge_version` is free text (src/store/migrations/0001_init.sql:81) and the change has no migration.

## Outside the change
- src/distill/pipeline.ts:356 · Every new distilled memory can still supersede older ones through `consolidate`. That status change is undone only by hand. This is not new, but version 2 titles now take part in it from the first drain.
