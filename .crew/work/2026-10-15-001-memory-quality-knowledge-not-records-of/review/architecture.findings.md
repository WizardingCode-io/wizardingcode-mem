## Findings
- F-1 · advisory · src/judge/types.ts:40 · Rubric question 3 (contracts). The change gives `DistillVerdict.durable` a new meaning: it is now the probability that a sentence counts as knowledge on its own, read from `knowledge_<i>` (src/judge/questions.ts:191-200, src/distill/pipeline.ts:122). It also changes what `titleIdx` means (src/judge/questions.ts:149 now asks which candidate "best states the knowledge"). The contract file was edited in this same diff (the `wording` field, types.ts:26-31), but its doc comments still give the old meanings: line 40 says "a durable, self-standing fact" and line 42 says "works best alone as a title". Spec section 7 ("Versions") and ADR 0023 record the decision to keep the field name, so this is not undeclared drift. Fix: reword the two comments in types.ts to the version 2 meaning and leave the field name as the spec says.
- F-2 · advisory · src/distill/pipeline.ts:117 · Rubric question 5 (Design placement). Spec section 8 is headed "The policy (`src/distill/policy.ts`)" and says "Everything that turns a probability into an action stays in this file". The judge contract says the same (types.ts:4-7, "distill/policy.ts"). The change writes the new rules in `buildDraft` in pipeline.ts instead (lines 117-160): the title must reach KNOWLEDGE_THRESHOLD, the fallback picks the surest sentence, and the `Context:` line needs CONTEXT_MIN_WORDS. policy.ts only gets the constants. `buildDraft` was already in pipeline.ts before this change, so the change extends an existing placement and does not cross a boundary. Fix, if the project wants the Design followed literally: move `buildDraft`'s decision rules into policy.ts, or reword spec section 8 to say policy.ts holds the thresholds and pipeline.ts applies them.
- F-3 · advisory · src/judge/heuristic.ts:869 (export `heuristicJudgeV1`) and src/distill/pipeline.ts:68, 173 (`storedDetail`, `toldInSession`, `unfilteredTexts` now exported) · Rubric question 6. Production modules now export code that only the proof script uses. ADR 0023 and CLAUDE.md name `heuristicJudgeV1`, and the comments name the proof as the reason. This matches how scripts/proof/moments.ts imports store functions, so no boundary is crossed. Noted only because these exports widen src/'s surface for scripts.
