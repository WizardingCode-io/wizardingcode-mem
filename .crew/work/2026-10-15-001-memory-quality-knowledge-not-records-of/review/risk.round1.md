# risk findings for 2026-10-15-001-memory-quality-knowledge-not-records-of
reviewer: review-risk
read: spec, plan, 14 files

## Findings
- F-1 · advisory · docs/superpowers/specs/2026-10-14-memory-quality-design.md:292 · The spec's answer to its main risk (version 2 drops knowledge in daily use) is "the lost target before the merge", but that target was missed on B (11 of 125 knowledge turns that version 1 kept, docs/adr/0023-memory-quality.md:64,84-94) and the author accepted the miss (D-12). What is left to undo it is a release, plus re-distilling the skipped turns through the cleanup item (D-1), which is not designed yet. This is recoverable only because `compact` runs by hand (src/cli/commands/compact.ts:24, src/ui/server.ts:421; RETENTION_DAYS 90 in src/store/compact.ts:12) and nothing runs it automatically, so the skipped turns' text is still there.
- F-2 · advisory · src/distill/pipeline.ts:302 · In the live drain, a turn the noise filter emptied and a turn the version 2 policy rejected both end as plain `skipped`. The names of the dropped sentences that `prepareTexts` builds (src/distill/pipeline.ts:229) are thrown away, and nothing is logged or counted. In the first hour after release, nobody could see the filter or the new title rule dropping knowledge, except by noticing that fewer memories appear. The spec names this as known (spec line 299), so it is advisory, but a skipped reason or a drop count would have made the first hour visible.
- F-3 · advisory · src/distill/policy.ts:12 · The code ships `KNOWLEDGE_THRESHOLD = 0.45`, but the item summary (.crew/work/2026-10-15-001-memory-quality-knowledge-not-records-of/spec.md:14), the design (docs/superpowers/specs/2026-10-14-memory-quality-design.md:203) and the plan (docs/superpowers/plans/2026-10-15-memory-quality.md:367,829) still say 0.5. The calibrated value is only in ADR 0023 (line 17, 54). Anyone rolling back or re-tuning from the spec would start from the wrong number.
- F-4 · advisory · docs/superpowers/plans/2026-10-15-memory-quality.md · The spec makes "a release" the only rollback (no runtime switch back to version 1, spec line 292, line 305). The plan names no release step: no version bump, no `bun run plugins`, no owner or order. So shipping the change, and reverting it, are both manual steps the plan leaves out.
- F-5 · advisory · src/judge/heuristic.ts:842-848 (diff) / src/judge/heuristic.ts `heuristicJudge` · Keyless installs, and the drain's fallback when TypeSafe fails, switch to heuristic version 2 straight away, with no flag. Its no-regression bounds D-6 and D-8 were met by only one or two turns (docs/adr/0023-memory-quality.md:64-65,116). `heuristicJudgeV1` exists but nothing can select it at runtime, so going back again needs a release.

## Outside the change
- src/distill/pipeline.ts:308 · Consolidation can still supersede existing version 1 memories with new version 2 drafts. This behaviour predates the change, and the change does not alter it.
- src/store/compact.ts:12 · Skipped turns, and the text that a later cleanup (D-1) would need, survive only until someone runs `compact`. Nothing warns that compacting now removes the only material the cleanup could recover from.

## Not answerable
- Third parties, the cost per turn on real traffic against version 1 · ADR 0023 measures the version 2/version 1 token ratio only on the golden turns (1.29). The about 6,008 tokens per real turn on B is version 2 only; version 1 was never measured on the same real turns, so the production cost increase is not known (the absolute cost per turn is small, about $0.0003).
