## Findings
- F-1 · advisory · /Users/andreagroferreira/AIProjects/ai-mem/src/distill/pipeline.ts:318 · In the live drain, `prepareTurn` computes the named drops (`PreparedTexts.dropped`), but `draftTurn` throws them away. Nothing is logged or counted. A turn the filter emptied, a turn the judge rejected and a turn with no knowledge title all end as `state = 'skipped'` with `last_error = NULL`. So if version 2 starts losing knowledge after the merge (the risk spec section 12, line 292, names), nobody sees it in the first hour or the first week, and the only measurement is the one-off proof. Advisory only because the spec states this ("Known", spec line 299) and gives a rollback (a release). A drop count per pattern in the drain's output, or a `doctor` line, would make the first hour visible.
- F-2 · advisory · /Users/andreagroferreira/AIProjects/ai-mem/docs/superpowers/specs/2026-10-14-memory-quality-design.md:292 · Rolling back is a release, but it does not undo what version 2 skipped in the meantime. Those turns stay `skipped`, and no shipped command re-distils them: the cleanup (D-1) is a separate, unbuilt item. `compact` deletes their text after `RETENTION_DAYS = 90` (/Users/andreagroferreira/AIProjects/ai-mem/src/store/compact.ts:12). The accepted loss on B (11 of 125 knowledge turns that version 1 kept, ADR 0023 line 64) therefore becomes permanent 90 days after the merge unless D-1 ships first. The spec states the window, so this is advisory, but nothing in the plan ties D-1 to that deadline.
- F-3 · advisory · /Users/andreagroferreira/AIProjects/ai-mem/src/distill/noise.ts:53 · `stripHost` cuts everything after a block tag that opens a line outside a fence and never closes. Say an answer quotes a `<system-reminder>` line without closing it, inside an indented or `>`-quoted passage that is not fenced: the rest of the answer is removed without a trace (see F-1). The proof saw only 1 such turn and has no live counterpart. The spec names this risk and only the proof reports it.
- F-4 · advisory · /Users/andreagroferreira/AIProjects/ai-mem/src/distill/noise.ts:104 · `withoutSentences` removes the first place in the text that matches a dropped sentence, not necessarily the place it was segmented from. For a clipped sentence it also removes up to the end of the line. The `assistant_final_message` sent to TypeSafe can therefore lose a kept sentence's surrounding text. The kept candidates are still sent separately, so the damage is limited to the judge's context, and nothing is written from it directly.

## Outside the change
- /Users/andreagroferreira/AIProjects/ai-mem/src/backfill/replace.ts:59 · `history replace-imports` archives every claude-mem import that history did not confirm. Version 2 stores fewer memories (303 against 400 on A and B, ADR 0023 line 66), so a `history import` run after this merge confirms fewer imports, and the next replace archives more of them. It can be undone (`history restore-imports`) and the count is shown before it runs, but no one has measured how big the effect is. The risk is already in the repository; this change makes it bigger.
- /Users/andreagroferreira/AIProjects/ai-mem/scripts/proof/quality.sh:75 · The `.backup` target is wrapped in single quotes inside the sqlite3 command, so a work dir whose path contains a `'` breaks the copy. It fails loudly, only in the proof, and never writes to the live store.
