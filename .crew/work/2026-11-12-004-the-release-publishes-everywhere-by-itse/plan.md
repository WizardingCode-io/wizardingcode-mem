## Conventions for `scripts/release/`

Every file uses only Bun's and Node's built-ins. Pure decisions live in `scripts/release/lib.ts` and are exported. The command files are `plan.ts`, `npm.ts`, `push.ts` and `token.ts`: each parses its arguments and environment, gathers facts, calls the pure decision, prints, and exits 0 or 1. They run other programs through one helper in `lib.ts`:

`run(cmd: string[], options?: { env?: Record<string, string | undefined>; cwd?: string }): { code: number; stdout: string; stderr: string }`, over `Bun.spawnSync` with both streams piped and `stdin: "ignore"`; a spawn that throws gives `{ code: 127, stdout: "", stderr: <the error's message> }`.

`ReleaseError` is a class exported from `lib.ts` whose message is one sentence. A command catches it at its top, prints `release: <message>` on standard error and exits 1. `summary(line: string): void` in `lib.ts` prints the line on standard output and appends it, with a newline, to the file named by `GITHUB_STEP_SUMMARY` when that is set. `output(name: string, value: string): void` appends `<name>=<value>` to the file named by `GITHUB_OUTPUT` when set.
