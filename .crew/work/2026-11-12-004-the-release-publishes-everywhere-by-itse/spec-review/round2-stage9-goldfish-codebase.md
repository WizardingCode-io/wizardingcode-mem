## Findings
- F-1 · Major · Step 12 (AC-43 e2e) · The plan tells the test to read the Codex hooks file from `codexContext("", env).hooksPath`, but that field does not exist. `src/install/codex.ts:50-63` returns `settingsPath` (`<CODEX_HOME or ~/.codex>/hooks.json`). The plan's fallback ("if that field has another name…, the file the Codex installer writes hooks to") hands a decision to the implementer when the plan should name `settingsPath`.
- F-2 · Major · Step 30 (distribute.yml) · The step describes the whole file but never mentions the top-level `permissions: {}`, the `concurrency` group `distribute` with `cancel-in-progress: false`, or `run-name: distribute ${{ inputs.tag }}`, all of which the spec requires. Someone following step 30 would leave out the empty default token scope and the concurrency guard. Step 29 only asserts "every clause of AC-52", and AC-52 does not mention `run-name` at all, so nothing ensures it gets written.
- F-3 · Major · Step 32 (README search) · The plan says `0.4.4` does not occur in README.md today. It does, twice, at README.md:113 (the 0.4.4 Gemini extension, which has nothing to do with npm). The plan says "unless the search finds one" but never says what to do when it does, so the implementer has to decide whether to edit an unrelated Gemini sentence.
- F-4 · Major · Step 24 (plan.ts gathering) · The plan does not say whether every fact is gathered before `decidePlan` runs, or what happens to the later reads when an earlier fact fails. With `tagSha` null, `git merge-base --is-ancestor <sha>`, `git cat-file -e <sha>:…` and `readContract(sha)` have no commit to use. When the ref is not main, or the tag is not on main, `readRelease` and `readEnvironment` still run, and a 403 or network failure there exits with "could not read …" before refusal 1 or 4 can be reported. That breaks the spec's "checked in order 1 to 9, the first that applies". Only the malformed-tag case is specified.
- F-5 · Nit · Step 2 (red run) · The claim that "the two existing functions fail … the not-a-version pairs" is partly false. For (`garbage`, `0.9.0`) both existing functions already answer true: `plugins/opencode/binary.js:42` turns `parseInt` NaN into 0, and the awk in `scripts/templates/wizardingcode-mem.sh:28` gives `"garbage"+0` = 0, which is less than 9. Of the not-a-version pairs, only (`0.9`, `0.9.0`) fails.
- F-6 · Nit · Step 2 · The phrase "the way `tests/unit/opencode-plugin.test.ts` loads that package" is wrong. That test imports a temporary file written from `pluginSource`, and reads `plugins/opencode/index.js` only as text. No existing test imports `plugins/opencode/binary.js`.
- F-7 · Nit · Step 4 (OLDER_JS) · `OLDER_JS` is JavaScript source held in a TypeScript string, and its regex contains `\d` and `\.`. In a plain template literal `\d` silently becomes `d`. The plan does not say to escape the backslashes or use `String.raw`, the way `opencodeBinary` already escapes `\\n` at scripts/plugins.ts:125. The AC-39 test would catch it, so this is a Nit.
- F-8 · Nit · Step 5 (shell older) · The awk program is left to the implementer. Two things are unstated. First, the comparison of alphanumeric identifiers is not pinned to byte order (no `LC_ALL=C`), so with mixed case an awk that collates by locale could disagree with JavaScript `<` and `Bun.semver.order`, and the table has no mixed-case pair to catch it. Second, an awk helper function closed by a line that is exactly `}` (column 0) would end `shellOlderBlock` early.
- F-9 · Nit · Step 12 · `hostBinary()` builds the binary. The plan does not mention the `beforeAll` timeout that `tests/e2e/agent.test.ts:13-15` uses (120_000). Without it bun's default hook timeout applies.
- F-10 · Nit · Step 26 (token.ts) · "`expiration` the response header" does not name the header. The spec names it `github-authentication-token-expiration`, and the `Bun.serve` stand-in has to send the same name.
- F-11 · Nit · Step 23 (commitAndPush) · Two cases are unstated. If `git pull --rebase` fails before a rebase starts (for example at the fetch), `git rebase --abort` itself fails, and the plan does not say whether to ignore that failure. And `git diff` on a dry run shows nothing for a new untracked file, such as a first `Formula/wizardingcode-mem.rb` in the tap.
- F-12 · Nit · Step 23 tests · Creating the annotated tag `v1.0.1` needs a committer identity. With `GIT_CONFIG_GLOBAL=/dev/null` none exists, and the plan does not say how the test supplies one.
- F-13 · Nit · Step 13 (resolveBinary, no-agent branch) · `cleanUpGemini(rest)` runs, and may remove files, before the `found.length === 0` check. Today its lines are printed after the loop. With the new early `return 1` on a `resolveBinary` error, those lines are never printed. The plan does not say whether to print them first (src/cli/commands/install.ts:172-182).
- F-14 · Nit · Steps 18 and 23 (manifests) · The fixture is to be "copied byte for byte … as read with `gh api …/contents/<path>`", but the contents API returns JSON with base64 content, so the decode step and the two paths are left implied. The marketplace edit in step 23 "reads the two manifests" without naming `.claude-plugin/marketplace.json` and `.agents/plugins/marketplace.json`.
- F-15 · Nit · Step 24 · For a pre-release, the plan does not say whether `previousPlain` and `decideHold` run, or what the `held` output is.
- F-16 · Nit · Step 19 · `REQUIRED_ASSETS` is "the six names" with no list. The names are only in the spec's refusal 8.
- F-17 · Nit · Steps 29 and 30 · The raw-file count of exactly four `secrets.MARKETPLACE_TOKEN` would also count any mention in the top comment that step 30 asks for. The plan does not say that the comment must not name it.
