## Findings
- F-1 · Major · Goals, item 6 · "The marketplace token cannot expire unannounced" is an absolute the design does not deliver. When the `github-authentication-token-expiration` header is absent, `token.ts` passes with "expiry unknown", and `--fail-under 30` cannot fail (line 160). GitHub can disable the weekly `token.yml` after 60 days without activity (line 233). "A failed scheduled run notifies the author" (line 162) depends on the author's GitHub notification settings, which the spec does not state. A reader would trust the weekly check to catch every expiry and miss these three gaps. Risks and rollback names none of them.
- F-2 · Nit · Design, "Two workflows, one door" / "The door, and what it rests on" / Alternatives line 211 / `token.yml` · "door" names three things. Line 97 makes it the environment `release`. Line 211's "one guard at the door covers every target" means `plan`'s highest-tag refusal. `door` is also the name of a `token.yml` job. The heading at line 71 uses the word before line 97 defines it. A reader has to work out which one each use means.
- F-3 · Nit · Problem, line 7 · "each was done by hand for 0.7.0 and 0.8.0" is false for the fourth item, which line 12 says "was not done at all" (npm is at 0.4.4). The sentence contradicts its own list.
- F-4 · Nit · Problem, line 7 · "Four things then wait for a hand" is an idiom where "four steps are then done by hand" would state the fact.
- F-5 · Nit · Critical User Journeys · J-8 comes before J-7. The order breaks the numbering, and readers who cite journeys by number will look in the wrong place.
- F-6 · Nit · Acceptance criteria · The IDs run AC-17 to AC-24, AC-36, AC-26 to AC-29, AC-37, AC-31 to AC-33, AC-38, AC-35. AC-25, AC-30 and AC-34 are missing and the order is mixed. A reader cannot tell whether the gaps are deliberate or criteria that were dropped.
- F-7 · Nit · Goals, item 3 · "the repeat path" is never defined. It seems to mean a `workflow_dispatch` of `distribute.yml`, but J-7 and J-8 cover a pushed tag and a dispatch from a branch, and only one of those is a repeat.
- F-8 · Nit · Goals, item 2 · "never harms a target that had succeeded" is vague. "Harms" can't be checked as written. The design's actual rule is "makes no new write to it", which AC-38's "already at" and npm's "already published" outcomes test.
- F-9 · Nit · Design, `plan`, line 117 · "three `git` answers" doesn't say which three. The reader has to infer them from refusals 3 to 5 before writing the pure function's input type.
- F-10 · Nit · Design, line 93 · "No job needs a job that may be skipped and must still run, so no status function is needed in any condition" is a double condition that is hard to parse. "Every job that needs a skipped job is itself skipped in the same case" would state it directly.
- F-11 · Nit · Design, line 101 vs line 115 · The same rule has two wordings, "selected branches: `main`" (the UI term) and "custom branch policies holding exactly the branch `main`" (the API term). The spec never says they are one condition.
- F-12 · Nit · Design, `token.ts`, line 160 · "GitHub documents the header only in a 2021 changelog" names no link and no read date. Other GitHub claims in the spec carry "read on 2026-11-12". The same applies to "Node 24.5 and later ship it" at line 136.
- F-13 · Nit · Design, `token.yml`, line 162 · "the schedule neither nags nor creates the environment" uses "nags", an informal word. The fact is that the run ends green and does not name the environment.
- F-14 · Nit · Design, "One version order", line 170 · "It lives in three texts" says "texts" for three implementations (TypeScript, JavaScript, shell), which reads oddly next to "byte for byte".
- F-15 · Nit · Alternatives, line 208 · "six copies in four languages" can't be checked against the spec. It names five writers and three languages (TypeScript, JavaScript, shell/awk), so the reader can't reconcile the count.
- F-16 · Nit · Alternatives, line 202 · "skip propagation that fails green" is compressed jargon. The meaning (a skipped dependency skips a needed job and the run still reports success) is not stated.
- F-17 · Nit · Risks and rollback, line 240 · "is expected to need the runbook's repairs once" is a forecast with no basis given. "the workflows' shape is pinned" is jargon for "AC-37 and AC-33 test the workflow files".
- F-18 · Nit · Critical User Journeys, J-3 · "npm says 'already published', the tap says 'already at 0.9.0'" gives the strings to npm and the tap. The run's summary lines say them (the `summaryLine` table).
- F-19 · Nit · Non-Functional Requirements, Security · "nothing reaches a shell by interpolation" is broader than the rule it summarises. Line 77 and AC-33 limit the rule to `distribute.yml` and `token.yml`, and `release.yml`'s new `distribute` job is under no such check. Today its `run:` scripts carry no `${{`, so the claim is true now but untested.
- F-20 · Nit · Out of scope · This section mostly repeats Non-Goals (pieces 2 and 3, the GitHub App, signatures, channel provenance, older npm versions). Only the ADR 0008 line is new.
- F-21 · Nit · Problem, line 3 · "six lenses" is the brief's internal term, left unexplained for a reader who has not read `concepts_brief.md`.
