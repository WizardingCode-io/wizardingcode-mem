## Findings
- F-1 · Major · Phase 1, AC-9 first bullet · The helper is defined as a runner that "delegates to `run` except for one named git subcommand". That cannot build two of the five cases. The `pull` case needs the first `push` faked as `[rejected]` and then `pull` failing with the header. The second-push case needs the first `push` faked as `[rejected]`, a real `pull`, and only the second `push` failing. A reader who builds the helper as written cannot express either case, and must design a per-call sequence (which call, which answer) that the plan never states.
- F-2 · Nit · Phase 1, AC-12 · `options()` in release-push.test.ts types `edit` as `(dir: string) => null`, but `editTap` and `editMarketplace` return `PushOptions["edit"]` (`Outcome | null`). Passing them fails `bun run typecheck`, which the plan requires after every phase. The plan does not say to widen the helper's type.
- F-3 · Nit · Phase 1, AC-12 · The plan does not say whether the tap and marketplace cases create new bare repositories through the reworked `repository(name, files)` helper or write to the `beforeEach` `other`. It also does not say that `beforeEach`'s two calls change to the record form.
- F-4 · Nit · Phase 2, gitStub · The clone failure prints `Authorization: Basic $ENCODED`, but the plan does not say where `ENCODED` comes from: interpolated by the test into the stub's text, set in the command's environment, or `$GIT_CONFIG_VALUE_0`, which the stub receives. The shape of `gitStub(options)` (moved-tag sha, clone fragment, the commit override that copies the manifest for AC-17) is also left to the reader.
- F-5 · Nit · Phase 2 step 3(d) and Phase 1 last AC-9 sentence · Step 3(d), "a passing run", does not name its target (tap or marketplace). The `token: null` complement does not name which git call's runner quotes the header.
- F-6 · Nit · Phase 2 step 5 / Files row for release-commands.test.ts · The deletion list names the `repository`, `tagged`, `env` and `git` helpers but not the `IDENTITY` constant or the `run` import, which become unused once those cases go. Lint catches both.
- F-7 · Nit · Phase 4, AC-13 · The test requires the number read from `release.yml` followed by " minutes" ("5 minutes"). The plan also says to write the paragraph "in the words of the spec's J-4", and J-4 says "five minutes". A paragraph copied from J-4 fails its own test.
- F-8 · Nit · Phase 4, AC-15 and documents · "the two rules, in the Decision paragraph on the token and in Limits" does not say which rule goes where. "The ADR also says writes are tested through `commitAndPush`" does not say whether the test asserts it, or with what string.
- F-9 · Nit · Phase 4, findings rows · The plan gives no status text for the piece 2 row, only that it must contain "piece 2", for example `deferred, to piece 2` as row 66 does. It also gives no source for "what the lenses found" (brief.md line 9 and concepts_brief.md hold it), so the reader writes that row's content without a reference.
