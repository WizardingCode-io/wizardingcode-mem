# structural findings for 2026-11-12-005-harden-the-releases-distribution-after-i

read: .crew/work/2026-11-12-005-harden-the-releases-distribution-after-i/probes/concept.md (whole), scripts/release/push.ts, scripts/install.sh (version_of, lines 94-117), scripts/templates/wizardingcode-mem.sh (lines 1-76), src/install/binary.ts (stagedVersion), npm/bin/wizardingcode-mem.js (installedVersion, older), scripts/plugins.ts (OLDER_JS, the generated installedVersion)

## Findings
- F-1 · Major · §2 The command reads no test override · Making `gitEnv` append after the environment's `GIT_CONFIG_COUNT` turns the inherited environment into a second way to steer the destination. Today `gitEnv` overwrites the count with 1, so any inherited `GIT_CONFIG_*` entries are dropped from authenticated calls. After the change, a `url.<x>.insteadOf` set by an earlier step, a composite action or a runner image flows into the clone and push that carry the token, on a runner too. `PUSH_REMOTE` at least was ignored on a runner. A reader would think the security lead's point is settled when the override has only moved from `PUSH_*` to `GIT_CONFIG_*`. A guard is needed: `gitEnv` refuses an inherited `insteadOf`/`pushInsteadOf` key when `GITHUB_ACTIONS` is true, or `REMOTES` is checked against `git remote get-url --push origin` after the clone. Without it, nothing in two years stops this from widening quietly.
- F-2 · Major · §2, `gitEnv` in scripts/release/push.ts · The commands also run without `GIT_CONFIG_GLOBAL`/`GIT_CONFIG_NOSYSTEM`, so the runner's global and system git configuration can rewrite the URL as well. The knowledge store already isolates git this way (`/dev/null` as global configuration). The release writer does not, and the concept does not say whether it should. Once the test depends on URL rewriting, the boundary of "where can the destination come from" stays undocumented and has no test.
- F-3 · Major · §2, the command's test · The test now depends on git's matching rules. `http.https://github.com/.extraheader` is matched against the rewritten URL, so the local path never receives the header, and the test cannot show that the header goes to the real https URL or that the appended index is correct. A future refactor could put the header at the wrong index, or overwrite the count again. That would silently drop the test's own rewrite, and the test would fail with a confusing clone error rather than an assertion about authentication. A unit test on `gitEnv` is needed: with an inherited count of N, the result has the header at key N, count N+1 and keys 0..N-1 unchanged. The command's test should not be the only thing holding it.
- F-4 · Nit · §2, `gitEnv` · The concept does not define "index = the existing count" for a malformed inherited value (empty, non-numeric, or keys present beyond the count). That parsing rule will be guessed at by whoever touches it next. State it: refuse anything but a non-negative integer.
- F-5 · Major · §1 The token's encoded form is masked · `tokenMask` repeats the credential's encoding (`x-access-token:` + token, base64) separately from the header `gitEnv` builds. Any future change to the header (a different user name, Bearer, a credential helper, a second token for the tap) needs the mask to change too, and nothing ties the two together. Derive both from one function that returns the header value, and mask exactly that string, with a test that `tokenMask(t)` covers the value `gitEnv(t, {})` puts in the environment.
- F-6 · Nit · §1 · GitHub masks whole strings line by line, and `GIT_TRACE_CURL` prints the data in chunks, so a value split across lines escapes the mask. The concept presents the mask as closing the debug re-run path. It is defence in depth on top of git's own redaction, and the runbook should say that so nobody later relies on it alone.
- F-7 · Nit · §1 · The mask is printed only when `GITHUB_ACTIONS` is `"true"`, the same signal that used to gate `PUSH_*`. When §2 removes that gate, the mask becomes the only reader of it. A later runner (act, a self-hosted wrapper, another CI) that does not set it would print nothing and mask nothing, with no warning. Logging one line ("no mask: not on a runner") off-runner would make the branch visible.
- F-8 · Major · §4 One rule for the version a staged binary answers · The "one rule" stays five hand-held implementations in three languages: `stagedVersion` (TypeScript), the generated `installedVersion` in `scripts/plugins.ts`, the handwritten shim `npm/bin/wizardingcode-mem.js`, `installed()` in the shell template, and `version_of` in the standalone `scripts/install.sh`. `older()` has a shared fixture (`tests/fixtures/version-order.ts`), but the reader rule only gets two ad hoc cases per writer. The next case (a stall, output on stderr, CRLF on Windows, an empty answer with exit 0) will be added to one or two readers and drift. Put the reader cases in one fixture table that every reader's test iterates, the same way the version order is held, and keep a rule like CLAUDE.md's ("a copy is never edited alone") for the reader too.
- F-9 · Major · §4, readers' time limits · The rule the concept states (exit 0, one version) leaves out the time limit, and the five readers already differ on it. `stagedVersion` and the npm shim give up after 10 s; the generated OpenCode `installedVersion`, the shell `installed()` and `install.sh`'s `version_of` wait forever. A staged binary that hangs on `--version` hangs the session-start hook of every plugin. "One rule" that still differs on this is the debt this item claims to pay. Either include the time limit in the rule, or name its absence as deliberate.
- F-10 · Major · §4, the rule split between reader and `older()` · Today the JavaScript readers reject a multi-line answer only because `older()`'s regex fails on it. In the shell, a multi-line `$1` reaches `awk -v a="$1"`, and BWK awk (macOS's) can reject a literal newline in `-v` and exit 2, which `older()` reads as "not older": kept. So whether the binary is replaced depends on the platform's awk. The concept should state that the reader itself returns empty on anything but one line, so `older()` never receives multi-line input. The test should run under the system awk on macOS, not only gawk.
- F-11 · Major · §4, scripts/install.sh `version_of` · `version_of` also checks the freshly downloaded binary (`new="$(version_of "$tmp")"`, "the downloaded binary does not run"). Tightening the rule there also changes the installer's acceptance of what it downloaded, and the concept does not mention this. A reader would change the staged-binary case and miss that a release binary whose `--version` exits non-zero would now stop every `curl | sh` install.
- F-12 · Major · §4, coupling to the binary's own `--version` · After this change, all five writers treat any `--version` answer other than exactly one version line with exit 0 as "no version, replace". The CLI's `--version` output therefore becomes a frozen contract. A future build that adds a second line (commit, build date) or a "wizardingcode-mem " prefix would make every writer replace every staged binary every time, so a downgrade by an older plugin is back. No test named in the concept holds the binary's own `--version` to that shape. One should hold it in `tests/`, next to the CLI.
- F-13 · Nit · §3 The dispatching job has a time limit · Giving one job of `release.yml` a timeout while leaving the others as "the debt point" means `tests/unit/deploy-files.test.ts` has to encode an exception, one job with and the rest without. That list will rot when the older jobs are revisited. Better to assert "every job of `release.yml` that has `timeout-minutes` has at most N" plus the one named job, or record the remaining jobs in the backlog row the test refers to. The figure 5 also has no stated basis, against the 15 used in `distribute.yml`.
- F-14 · Nit · §4 · The concept says "the plugins' scripts are regenerated" but does not name `bun run plugins` or the generated targets (`plugin/wizardingcode-mem.sh` and the per-agent copies). It also does not say whether a test fails when a generated copy differs from the template. If none does, a hand edit to one copy will drift unnoticed.
