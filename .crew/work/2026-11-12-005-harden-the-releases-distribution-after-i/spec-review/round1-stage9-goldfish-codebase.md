## Findings
- F-1 · Major · Phase 1, AC-12 · The plan calls `commitAndPush(options(editTap(...), …))` and `options(editMarketplace(...))`, but the `options` helper in tests/integration/release-push.test.ts:70-71 types `edit` as `(dir: string) => null`, while both edits return `PushOptions["edit"]`, which is `(dir) => Outcome | null`. tsconfig.json includes `tests`, so `bun run typecheck` fails the phase unless the helper is widened, and the plan does not say to widen it (today's left-alone case gets around it with `as never`, line 150).
- F-2 · Major · Phase 1, AC-9 · The helper is specified as "delegates to `run` except for one named git subcommand, for which it returns code 1", but two of the five sites cannot be reached that way. The rebase site needs the first `push` faked as `[rejected]` and `pull` faked as failing, which is two subcommands. The second-push site needs the first `push` to answer `[rejected]` and the second `push` to fail with the header, which is the same subcommand answered differently by call count. The implementer has to design the fake for these two cases.
- F-3 · Major · Phase 2, AC-10 (a) · The stub's clone prints `Authorization: Basic $ENCODED`, but nothing says where `ENCODED` comes from. The `stub` helper (release-commands.test.ts:36-43) writes a shell script, and push.ts passes the stub only `process.env` plus the gitEnv keys. If `$ENCODED` is left as an unset shell variable, the clone's error carries no value: the post-change case then passes without testing redaction, and stays red before the change only because the mask line is missing. The plan must say to interpolate the computed value into the stub's text in JavaScript, or to read it from `$GIT_CONFIG_VALUE_0`.
- F-4 · Major · Phase 2, gitStub and AC-10 (b) · The stub's cases list `status --porcelain` but not `status --short` or `diff`, which the dry-run path calls through `must` (push.ts:117-119). With "the same stub", the stub's fallback answers `unexpected git …` with exit 64, so the dry-run case ends in `tap: failed: git status failed…` with exit 1. The case asserts only that the mask line comes first, so it passes while the command's dry run (J-2) is never exercised.
- F-5 · Nit · Phase 2 step 5 · Deleting the three local-repository cases and the `repository`, `tagged`, `env` and `git` helpers also leaves the `IDENTITY` constant and the `run` import (release-commands.test.ts:14, 361-368) used by nothing, and the plan does not name them for removal. biome flags the unused import and variable.
- F-6 · Nit · Phase 2 step 4 · The step says to print the mask as the "first statement" of the command's body and also to read `token` "once before `need("VERSION")`", but it never states how the token is read. The existing expression `process.env.MARKETPLACE_TOKEN || null` (push.ts:227), which turns an empty secret into no token, should be named as the one kept.
- F-7 · Nit · Phase 4, AC-15 · "The ADR also says writes are tested through `commitAndPush`" gives no exact string for the test to assert, unlike the other AC-15 checks, so the implementer has to choose one.
- F-8 · Nit · spec.md Design 2 · "every call when no token is set, runs with the environment as inherited" is not exact. With no token, the clone and push still get `gitEnv(null, …)`, which adds `GIT_TERMINAL_PROMPT: "0"` (push.ts:37-38, 98).
