## Findings
- F-1 · advisory · tests/integration/team-mirror.test.ts:607 · AC-49 ("the server runs `serve mirror` as a child"): the test injects `mirrorCommand` with its own copy of the arguments, so the server's default at src/team/server.ts:125 (`selfCommand("serve", "mirror", "--data", dir)`) runs in no test. A regression on that line alone would stay green. Reverting the round-1 fix in the CLI would fail. A unit check of the default command would close this (Q1, residual).
- F-2 · advisory · tests/unit/team-contract.test.ts:30 · AC-57: the fingerprint covers `RESULT_SHAPES`, which is a hand-written list. No test compares it with the keys the server actually answers (push result, feed item, pull page, join, me). A field added to a real answer without touching the list changes no fingerprint (Q1, residual of round-1 F-2).
- F-3 · advisory · tests/integration/team-mirror.test.ts:534 · AC-49, a renewal before every git call: the test proves this by counting `ctx.now()` reads. That count also includes the reads for the lease take, each commit's time and the run record. The test fails when the behaviour reverts, but it is tied to how many times the implementation reads the clock: any extra, unrelated `now()` call breaks it (Q5).
- F-4 · advisory · tests/integration/team-process.test.ts:194 · AC-51 says the logs never contain "a code (after the bootstrap line)": the logs are checked only for the bootstrap code. No test checks a log for an invitation code minted through `POST /v1/invitations`, or for the code of a refused join. team-auth.test.ts:145-148 checks only `audit.detail`, never `t.lines`. A refusal or mint path that logged its code would pass (Q1, residual of round-1 F-5).
- F-5 · advisory · tests/unit/team-db.test.ts:109 · AC-44, "closes its handle when a module migration fails": reopening the file does not show that the earlier handle was closed (carried over from round 1).
- F-6 · advisory · tests/integration/team-push.test.ts:751 · AC-45/AC-47, "an idempotent retry is not charged": the test shows the retry is applied with an empty bucket. It does not show that the retry leaves the bucket's level unchanged (carried over from round 1).
- F-7 · advisory · tests/integration/team-mirror.test.ts:648 · AC-49, "no request waits on git": the 500 ms timing still runs with a no-op `mirrorChild` (carried over from round 1).
- F-8 · advisory · tests/unit/deploy-files.test.ts:50 · AC-54: the file half is asserted by this test but sits under an observed criterion, so the item records no red run for it (carried over; the judge lowered it to advisory in round 1).
