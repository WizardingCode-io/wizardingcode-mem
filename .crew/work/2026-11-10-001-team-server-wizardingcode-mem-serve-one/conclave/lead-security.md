## Returns
- R-1 · .crew/work/2026-11-10-001-team-server-wizardingcode-mem-serve-one/spec.md:109 (the trust-proxy rule) and :262 (AC-17) · `https required` applies only to "an authenticated request". `POST /v1/join` is unauthenticated, but its answer is the one place the device token appears (spec.md:147). Behind the proxy a join over plain http would send the token in the clear, and the invitation code travels the same way in the request. Make the rule cover every route except `/v1/health`, join included. Add to AC-17 that, with `trustProxy` and no `X-Forwarded-Proto: https`, `join` is 400 `https required` and spends no invitation. `/v1/health` must stay exempt, because Docker's probe sends no proxy headers.
- R-2 · .crew/work/2026-11-10-001-team-server-wizardingcode-mem-serve-one/spec.md:196 (the mirror) and :266 (AC-21) · The member repository folder is `repos/members/<member id>-<name slug>/`, but nothing defines the name slug. A member name only has to pass `authorNameProblem` (1 to 80 characters, no line break, not starting with `agent:`), so it may hold `/`, `..`, `.`, a NUL or a leading dash. The spec has no rule for the slug and no hostile-name test, and AC-21 tests only ordinary names. Define the slug (for example lower-case `[a-z0-9-]` only, collapsed, capped in length, empty becoming `member`). Say that the folder is built from the member id plus that slug and never from the raw name. Add to AC-21 a case with names such as `../x`, `a/b`, `.` and `-rf`, asserting that every folder stays directly under `repos/members/`.
- R-3 · .crew/work/2026-11-10-001-team-server-wizardingcode-mem-serve-one/spec.md:208 (the ci.yml step) and :271 (AC-26) · AC-26 is "observed" and claims "uid 10001 with a read-only root filesystem". The CI step it rests on only starts a container "with a temporary volume" and runs `serve health` and `id -u`. It never starts the container read-only, so nothing proves the server works on a read-only root. A path that wants to write outside `/data` and `/tmp` would pass CI and fail in production under `read_only: true`. The step must start the container with the compose file's hardening: `--read-only --tmpfs /tmp --cap-drop ALL --security-opt no-new-privileges:true`, and run it with `--init`. It must then assert `health`, uid 10001 and exit code 0 under those flags. AC-26 should name those flags.
- R-4 · .crew/work/2026-11-10-001-team-server-wizardingcode-mem-serve-one/spec.md:164 and :176 (push shape rules) and :264-265 (AC-19, AC-20) · "Shape" is checked only by key list (`OUTGOING_ENTRY_KEYS`, `OUTGOING_MEMORY_KEYS`). AC-19 and AC-20 test an extra or missing key, but never a wrong value type. `src/sharing/types.ts:146-173` has `frontmatter`, `body`, `title` and `memoryKind` as strings, `importance`, `version` and the timestamps as numbers, and `kind` as a literal. A non-string `frontmatter` would be a 500, and the memory payload is "stored as JSON verbatim" and served to other members' agents. A member's device could therefore store arbitrary types or huge `memoryKind` and `status` strings. Memories also have no per-item byte cap: D-15's 256 KiB covers entries only, so a memory is bounded only by the 1 MiB body. The spec must require typed validation of every field, with finite numbers and the `kind` literal. It must give the memory `memoryKind` and `status` a pattern or an enumeration, and give a memory a byte cap (`refused size`, for example the same 256 KiB). AC-19 and AC-20 must name tests for a wrong type, an oversized memory and an out-of-grammar `memoryKind`, each answering `refused shape` or `refused size` and never 500.
