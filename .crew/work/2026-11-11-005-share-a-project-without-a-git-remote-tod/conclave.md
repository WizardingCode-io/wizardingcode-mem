# Conclave: shared names (a project without a git remote)

The gap round over the checklists `endpoint`, `migration-or-restore`, `sync`, `screen` and `deletion` (the five reads are on the item), for the spec in `spec.md`.

## Assumed by good practice

- Every new route is behind the device token and the devices bucket like its neighbours; the list of names is paged (50, at most 200) and ordered; the inputs (`alias`, `after`, the path parameter) are validated at the boundary by the leaf's grammar before any SQL; refusals are in the server's problem shape (`{ error }`), never a stack (endpoint). AC-25.
- The four new client routes answer the viewer's refusal shape (`{ error }` with a status) and the two new CLI subcommands the CLI's usage and exit codes; every local refusal is decided before the server is asked, and nothing is written when the server cannot be asked (endpoint). AC-22, AC-23.
- Migration 8 and team schema 2 are run once by the existing runners, which copy the file first; both are forward-only like every migration of this repository, and the reason neither is reversed in place is in the spec (an older binary or image refuses the newer file and the copy is the way back) (migration-or-restore). AC-2, AC-25.
- The sync's truth per field is unchanged (ADR 0027): a shared or project entry's current text is the server's once sent; a memory's truth is its device; the ledger line per item and direction, the idempotent sweep and the bounded first run stay; the registry is the server's and the client only reads it (sync). AC-16, AC-8.
- Every state the diff adds to the dock and the Servers page is enumerated on AC-22 and captured at the three widths in both schemes; labels tied to inputs; keyboard and focus; copy in English; the list of names asked once per server when the section opens and never on a hook (screen). AC-22.
- Forgetting a name deletes one alias row and nothing else (the project, its memories and its entries stay); it is refused while a level is bound to the name; leaving a name withdraws through the server's tombstones (a soft removal the admin can reinstate); the operator's purge is the erasure, of the items and, since revision 2, of the name; every change writes a `sharing_changes` row (deletion). AC-3, AC-8, AC-25.

## Decisions only the user can make

D-1 to D-7 were taken by the person on 2026-11-11 ("sim força", the defaults) and are recorded on the item. The checklists raise five more, each settled by one of them or by an earlier record:

- Who may create a name, and whether existing members have it today (endpoint): any member, as any member may push a project entry today (ADR 0026 D-12); by D-2 (the registry is created once, by one member).
- Which fields the list exposes (endpoint): the name, its creator's id and name (already on every feed item), the counts and the last change time; never a remote alias; by the brief's assumption the person confirmed (names only).
- What comes back after a rollback (migration-or-restore): the upgrade's copy, on either side; the names created since are lost with the server's copy and the clients re-send what the copy lacks; by D-4 and D-5 and ADR 0026's rollback.
- Erasure or deactivation when a name is left (deletion): a withdrawal (tombstones, reinstatable) as for a remote-named project; erasure stays the operator's purge; by ADR 0026 and ADR 0027.
- The focal moment of the pages (screen): none, motion none, by ADR 0025 D-18 (the app pattern); the dark scheme exists.

## Proposals

- Ask the server for its names once when the dock's field opens, so the create and join states are shown before anything is written: taken, in AC-22.
- A timeline line per name created, replaced or forgotten: taken, as a `sharing_changes` row `name:<id>` on the client (AC-3) and the audit rows `name created` and `name purged` on the server (AC-25).
- A per-name read-out of what arrived (entries, memories, members, the last time), so "why does my teammate's project never arrive" has an answer: taken, in AC-11.
- A dry run of the two migrations: not taken; migration 8 is one index and schema 2 four renames and three creates, each behind the runner's copy.

## Warnings

- The viewer's `GET /api/servers/<id>/names` follows every page of the server's list in one answer: a list with no limit at the proxy. The spec caps it at 1,000 names; the server's own pages stay bounded. Advisory, O-1, AC-22.
- "Forget name" is a hard delete of an alias row behind a button: the row is the only thing deleted, it is refused while bound, and it is logged. Advisory, O-2, AC-3.
- Any member can create names without a cap on the registry's size: the devices bucket bounds the rate; the operator's `serve purge name` removes one; an admin's API route is a later item. Advisory, O-3, AC-25.
