- F-1 · Blocker · Acceptance criteria, AC-29 (serve purge name) · AC-29 asserts that "the `purged` keys of its purged entries" still carry the name string, but The operator's erasure (line 171) says "the `purged` table's keys are the entry's uuid or the device's memory key and hold no alias". - F-2 · Major · Journey 6, Documents (ADR 0028 Known limits), Risks ("A sensitive or wrong name") · Three sections say the string stays "in the entries' keys". Line 171 gives the exact places: the `changes` rows' uid, the withdrawn entry and memory rows' `project_alias`, and the audit rows. An ADR or runbook author working from "the entries' keys" would document a place that does not hold the string and leave out the ones that do. Fix: use line 171's list in all four places.
- F-3 · Major · Acceptance criteria, AC-26 against AC-34 and The two-phase write · AC-26 says "the two boundary tests pass unchanged", and line 100 says they "need no change". Line 124 and AC-34 put `src/sync/binding.ts` on `tests/unit/sync-boundary.test.ts`'s quiet list, which is an edit to that test. A builder cannot meet both criteria as written. Fix: AC-26 should say the boundary tests are unchanged apart from AC-34's quiet-list entry.
- F-4 · Major · Routes, PUT /api/projects/<id>/sharing and the refusal-body bullet · Line 213 says every sharing refusal is `{ error: <sentence>, reason: <code>, …extra }` and that the dock switches on `reason`. Line 210 writes the new refusals as `{ error: "contract" }`, `{ error: "exists", name }`, `{ error: "unknown-name" }` and `{ error: "server" }`, with the code in `error` and no `reason`. A builder who follows line 210 sends bodies the dock cannot switch on. Fix: write line 210's bodies in line 213's shape.
- F-5 · Major · Routes (GET /api/servers/<id>/names) against AC-33 · The route gives 404 `unknown-server` for an unknown id, but AC-33 tests for 404 `no such server`. One fact has two values, so either the test or the route ends up wrong. Fix: pick one code and use it in both places.
- F-6 · Major · The name of a project, setLevel's rename (line 116), forgetName (line 118) · "one change row `name:<id>`" and "logs `name:<id>`" use `<id>` where Terms defines **Name id** as the registry's id. AC-3 logs `project:<id>@<server>`, which suggests the project id. A reader could key the change row on the registry id. Fix: write `name:<project id>`, or whichever id is meant.
- F-7 · Major · Goals, goal 5 · "released within a minute of the server's upgrade" leaves out a condition that line 177 states: "while the sync runs". If the sync is not running, nothing re-reads `/v1/me`, so the hold does not end. A tester checking goal 5 as written would expect a release that never comes. Fix: add "while the sync runs (or at the next dock or CLI action)", as line 177 and line 253 do.
- F-8 · Major · Rollout and rollback, midway check · The midway check names "AC-17's header-1 case", but AC-17 is not in this document (line 290 sends replaced ids to `conclave.md`). The case is in AC-31. The phase C gate points at a criterion the reader cannot find here. Fix: cite AC-31.

The Terms entry lists four sources (the join, `/v1/me` at start and at each sweep, `/v1/me` once before the dock or CLI refuses, a 409's accepted list), and line 177 adds a fifth: a bare 404 sets the row to 1.
