## Findings
- F-1 · Major · The viewer (lines 180-182) and The CLI (line 205) · The pinned copy strings are written as code spans with backslash-escaped backticks inside them, such as `New: you create \`<slug>\` on <server>` and `Create \`<slug>\` on <server>, visible to every member, …`. CommonMark does not honour backslash escapes inside code spans, so each span ends at the first `\` and the text after it renders as plain text. The `<slug>`, `<server>` and `<member>` placeholders then render as raw HTML and disappear. AC-22 pins these strings "word for word" in the Vue sources, so a reader working from the rendered spec would copy corrupted strings into the sources. Fix: use double-backtick spans (`` `` ``) for these strings.
- F-2 · Major · Critical user journeys (lines 67-73) and setLevel refusals (lines 99-101) · Placeholders written outside code spans are valid inline HTML tags and are dropped when the Markdown is rendered. Examples: "on <server>" in journeys 1, 3, 4 and 7; "receive it into <project>?" in journey 2; "<other project>" in the `name-taken` sentence (`<other project>` parses as tag `other` with attribute `project`). A reader of the rendered spec sees "on ." in the very sentences the confirmations must reproduce, and would build the confirmation text without the server or project name.
