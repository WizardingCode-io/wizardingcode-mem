- F-2 · Blocker · Task 3 (`backups/*-v8-*.db`) and task 9 (`team-<ms>-v2-<pid>.db`) · False: src/store/db.ts `migrateFile` names the copy after the version before the upgrade (`backupVersion` returns the current user_version), and tests/unit/team-db.test.ts:79 and :316 already assert `team-…-v1-…`. A 7 to 8 upgrade leaves `-v7-` and a team 1 to 2 upgrade leaves `-v1-`. As written the tests fail against correct code, or they push the builder to change the backup naming. Fix: assert `-v7-` and `-v1-`.
- F-3 · Major · Task 9 (`openTeamExisting` with `latest` 1) and AC-25 · src/team/db.ts `openTeamExisting(dir)` takes no `latest`. It always uses TEAM_LATEST, so after the bump it cannot model a 0.7.0 open. The builder has to choose between adding an options parameter and calling `openExistingFile(dir, TEAM_DB_FILE, { before: requireTeamSchema, latest: 1 })` in the test. Fix: name which one, with the signature.
- F-4 · Major · Task 9 (team-serve-cli.test.ts: "the existing seam of openTeamForWrite's options, or a test that runs the binary …") and task 9 ("a spy on store.ts's nameByAlias, or through the SQL trace of bun:sqlite") · Both leave a test design open, and bun:sqlite has no SQL trace hook that I know of. Fix: pick one mechanism for each (for example, run `serve` through spawnCli against a directory migrated to schema 2 and assert exit 3; for the no-SQL assertion, a counted wrapper or a named spyOn on the module namespace that is known to work under Bun).
- F-5 · Major · Task 10 ("`grep -n remote_alias src/team` ends empty") · This cannot hold: src/team/migrations/0001_team_init.sql keeps `remote_alias` permanently, because migration 2 renames the column. A literal builder would edit migration 1, which breaks every existing team.db. Fix: scope the check to src/team/*.ts, or exclude migrations/.
- F-6 · Major · Task 23 (`createName`, `nameByAlias` added to client.ts) · src/sync/client.ts `failureOf` maps every 409 to `{ kind: "contract", accepted }` and drops the body. So `POST /v1/names` answering 409 `{ error: "exists", name }` arrives as a contract failure with accepted [], and bindName can neither return `exists` with the item nor tell it from a skew. Fix: specify the new failure kind (for example `{ kind: "exists", status: 409, name: NameItemShape }`, chosen when body.error is "exists") and say how 404 `unknown-name` is told from the bare 404 `not found` (by body.error).
- F-7 · Major · Task 14 (src/sync/inbound.ts, src/sync/outbound.ts) · Today the sweep and pull clients are built without the stored contract (`new SyncClient(ctx, { url, token })` at inbound.ts:459, outbound.ts:307 and outbound.ts:904 `withdrawAll`), so the header is always CONTRACT. The spec's "the header sent is the stored value" is not true of the code, and the plan never says to pass `contract: server.contract`. Without that, a client at the old server takes a 409 on every request and the "contract spoken" never takes effect. `withdrawAll` also gets no 409 retry rule. Fix: name the three constructions and the retry for withdrawAll.
- F-8 · Major · Task 13 (sync-contract.test.ts uses `world()` with a server at `{ current: 1, accepted: [1] }`) and task 15 (world gains `{ named?: true }`) · `world(level)` takes only a positional level and has no way to start the test server with a contract, and task 15, which edits world, comes after task 13. Also, once task 14 makes the join store min(CONTRACT, 1) = 1, the "first pull answers 409" expectation only holds if the test forces the row to 2 first, and the plan does not say so. Fix: give world's new signature in full (for example `world(level, { named?, contract? })`), move that helper edit to task 13, and state the row setup for the 409 case.
- F-9 · Major · Phase E, task 20 ("this task's green run follows task 22's") against the header's "every phase leaves bun run check green" · Phase E ends with task 19's tests red and task 20 not compilable (it calls `bindName` from src/sync/binding.ts, which does not exist until Phase F). Fix: move task 22/23's bindName and its test before Phase E, or merge E and F into one phase.
- F-10 · Major · Task 6 and the Viewer bullet (`forgetName`, `DELETE /api/projects/<id>/name`) · No return type for `forgetName`, and no behaviour for a project that carries no name or for an unknown project id: route status, body, whether it logs or bumps the counter. - F-11 · Major · The wire and the shapes, Viewer bullet, and task 19 (refusal bodies such as `409 has-remote|name-taken|…`) · Existing refusals answer `{ error: <sentence> }` (src/ui/api.ts `refused`, and ui-sharing.test.ts asserts `toContain("no git remote")`). Fix: give one body shape for every refusal (for example `{ error: <sentence>, reason: <code>, other?, named? }`) and the assertion task 19 makes.
