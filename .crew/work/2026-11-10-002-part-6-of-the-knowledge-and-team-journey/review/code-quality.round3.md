## Findings
- F-1 · defect · src/modules/knowledge/index-store.ts:1116 · `HELD_PIN` and its docstring ("The own entries whose pin is held") name the held pins, but the fragment is `NOT EXISTS (… APPLIED_ROW_OF_ENTRY)`, and `pinnedEntries` (line 1238) uses it to keep only the pins that are *not* held. The name says the opposite of what the predicate selects (Q3).
- F-2 · defect · src/ui/api.ts:1045 · `destinationFor` writes the destination rule again (`boundServerOf`, else `policy.server`, else `TEAM_DESTINATION`, lines 1045-1048) instead of calling `destinationOf` (src/sharing/levels.ts:126). That function's docstring says it is "One rule for `status`, the viewer's project list and the viewer's level routes", but the level routes (`previewSharing` at api.ts:992 and `setProjectSharing` at api.ts:1075) go through this copy. This is round 2's F-16 duplication in a new place (Q2).
- F-3 · defect · src/sharing/levels.ts:93 · `aliasBoundTo` ("bound to the server under the alias") matches any alias the project has (`JOIN project_aliases a ON a.project_id = p.id … AND a.alias = ?`). `boundAliasesOf` (levels.ts:79), a few lines above, ties the alias to `l.bound_alias`, and so does `receivedMarks` (src/retrieve/received.ts:48). So two rules for "bound under this alias" in one file already disagree for a project with two remote aliases (Q2/Q3).
- F-4 · defect · src/sync/received.ts:302 · `reindexReceived` builds the entry uid by hand (`project:${alias}:${id}` / `${scope}:${id}`) instead of calling `entryUid` (src/sharing/types.ts:345), which src/sync can import. The copy already differs: for a project folder with no manifest alias it writes `project:<uuid>`, a uid `parseEntryUid` cannot parse, where `entryUid` refuses (Q2).
- F-5 · defect · src/sync/outbound.ts:750 · `withdrawals` gets the alias from `projectOf` (which calls `parseEntryUid`) and then the scope of the same uid from `row.itemUid.split(":")[0]`. outbound.ts:385 gets the uuid with `entry.uid.split(":").pop()`. ADR 0027 says of the third round that "the entry uid is parsed by `parseEntryUid` alone", which is not yet true (Q2).
- F-6 · defect · src/modules/knowledge/received-ref.ts:34 · the uuid of a received hit is taken from its uid with `split(":").pop()` here, again in tools.ts:263 (`renderBlock`'s `id:` line) and in src/cli/commands/knowledge.ts:244 (`take`). `knowledge_received.id` already holds that uuid, and `hitOfReceived` (index-store.ts) drops it, so the one derivation is written three times (Q2).
- F-7 · defect · src/sync/outbound.ts:215 · `projectOf(item.uid) ?? null`: `projectOf` already returns `string | null`, so the `?? null` gives the value it was handed on both sides. This is the same no-op shape as round 2's upheld ternary (Q4).
- F-8 · defect · src/sync/outbound.ts:512 · the conversion of a failed answer into `recordAnswer` (`error: ${kind}${error}`, `retryAfterMs` for a rate, `requestId` when given) is written in three places here (512-519, 872-879, 932-939) and again in src/sync/inbound.ts:436-443. Round 2 found these copies drifting (F-31), and they were brought in line by hand rather than made one function (Q2).
- F-9 · advisory · src/cli/commands/share.ts:264 · after `write(true)` the store cannot answer `needs-confirm`, so `if (!outcome.ok) throw new Refusal(…)` cannot fire. It is there only to narrow the type; src/cli/commands/knowledge.ts:238 (`hit.received === undefined` after `resolveReceivedRef`) is the same kind of guard (Q9).
- F-10 · advisory · src/cli/commands/knowledge.ts:242 · for a workspace hit the refusal says "take it with --scope shared", and the same `hit.scope !== scope` check then refuses that too. The hint names a scope that cannot work (Q3).
- F-11 · advisory · src/cli/commands/share.ts:177 · a local `destinationOf(serverId)` (`serverId ?? TEAM_DESTINATION`) has the same name as the sharing module's `destinationOf`, which applies another rule, and share.ts:354 adds a third inline variant (`boundServerOf(…) ?? destination`) (Q3).
- F-12 · advisory · src/ui/servers-api.ts:230 · `listOf` and share.ts:253-255 each turn a list value into an array (`none`, empty, split) before `setServerLists`, which then rejoins and re-parses it with `parseShareList`. Two small parsers of one setting format (Q2, boilerplate).
