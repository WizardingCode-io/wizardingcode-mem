## Findings
- F-1 · defect · ui/src/components/settings/Sharing.vue:219 · /settings#sharing in states one and several at 360 (a mandatory width that AC-90 names), in both schemes: the root rows put the switch label on the same flex line as the `flex-none` mono count. The count does not wrap, so it runs over the label: "Workspace knowledge" collides with "0 entries would leave" or "1 entry would leave", and "Shared repository knowledge" sits under "0 entries would leave". The help text beneath wraps to one word per line. Line 219-220 predates this diff, but the overlap shows in two declared states of this change at a mandatory width, now that Settings.vue (in the diff) gives the card the full width (review/ui/settings-several@360-dark.png, review/ui/settings-one@360-light.png)
- F-2 · advisory · ui/src/components/settings/Servers.vue:257 · /settings#servers muted: the pill reads "Muted" but takes its tone from `STATE_TONE[s.state]`, which is the `ok` tone. A muted server therefore wears the same green as a healthy "Ok", so the colour says "fine" for a server whose entries no agent is shown (review/ui/settings-muted@1280-dark.png, review/ui/settings-listed@1280-dark.png)
- F-3 · advisory · ui/src/components/settings/Servers.vue:56 · /settings#servers held and resuming: the hold captured is empty. The row says "A hold since the restore: the next sync withdraws nothing until you resume.", and Resume… says "Nothing is held for 127.0.0.1:49407 now; the hold is released." The branch the state exists for (n withdrawals held, with the per-project lines) is still in no capture. This is better than round 2's "0 withdrawals held", but the two sentences still pull against each other (review/ui/settings-held@768-dark.png, review/ui/settings-resuming@768-light.png)
- F-4 · advisory · ui/src/components/settings/Servers.vue:101 · /settings#servers error: the code is cleared only on success (line 101), so after a refusal the invitation field still holds the refused code (30 dots in the capture). The manifest's note says "the form stays filled but for the code", so the capture and the note disagree. Keeping a used-once refused code in the field invites a second refused try (review/ui/settings-error@1280-dark.png)
- F-5 · advisory · ui/src/components/Settings.vue:111 · /settings at 360: under 640px the whole nav is hidden (Settings.vue:80 swaps in the select). Its footer sentence "Kept in the data directory, readable by you only. The environment wins over the file; for sharing it can only narrow." goes with it, so a phone-width reader never sees that the environment can only narrow sharing. It is visible at 1280 and 768 (review/ui/settings-several@360-dark.png, review/ui/settings-several@1280-dark.png)
